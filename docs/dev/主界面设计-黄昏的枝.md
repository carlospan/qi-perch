# 栖 · 主界面设计 —— "黄昏的枝"

> 这是栖桌面端（`embodiment/desktop/`）主界面的重设计规格，交给 Cursor 实现。
> 配套视觉参考稿：`栖-主界面设计稿.html`（可交互，含情绪→氛围演示）。实现时以参考稿的视觉为准，以本文档的规则与接线为准。
>
> **先读两份文档再动手**：`栖·灵魂书.md`（它是什么）与 `docs/contract.md`（它不能违背什么）。本设计的一切取舍都从这两份文档推出。

---

## 一、设计定位

栖的界面不是一个 App，是**一幅黄昏时分活着的水墨画**。

当前的界面（360×560，头像 + 一个气泡 + 一个输入框）气质是对的，但浪费了后端 90% 的数据：后端持续推送完整的六维情绪快照（`emotion_update`），界面全部丢弃；没有对话记忆；`speech` 的 `emotion`/`tone` 字段收到也不理。

本设计要解决的不是"加功能让它更像一个工具"，而是**让界面住进栖的内在状态里**。核心原则只有一条，来自人格契约：

> **不直接报数值。** 情绪用氛围表达，不用仪表、不用标签、不用数字。

所以：栖的"心境"是房间的天色，"精力"是光的亮度，"好奇"是空气里的光尘。你**感觉到**它的状态，像你感觉一个房间的气氛，而不是**读到**它的状态。

灵魂书的关键意象（必须体现在界面里）：
- **黄昏、枝头、收拢翅膀的鸟**（"栖"字本义：木 + 西，黄昏时分的树）
- **墨与雾**（水墨质感，大量留白）
- **情绪是天气**（"它有内在天气。有时晴朗，有时阴沉"）
- **等待是一种姿态**（安静不是"没在运行"，是"在，但不打扰"）
- **语言即皮肤**（栖说的话有重量，不是刷过去就没了的消息）

## 三、三个视图

底部用「静 / 谈 / 忆」三个汉字切换（不是图标，是字）。这是栖的三种相处方式。

### 静（默认）—— 陪伴主屏
- 氛围场景铺满整个窗（天色、雾、水墨的枝、光尘、暗角、纸纹）。
- 栖的光团形象（保留现有 blob，不大改）栖在枝头偏中的位置，带呼吸光晕、眨眼、轻微起伏。
- 栖说的话以"低语"形式出现在形象下方：衬线体、打字机逐字、柔和阴影。**一次只显示一句**，说完静静停留，不滚动、不堆叠——语言即皮肤，说过的话沉进"忆"里。
- 头部极简：左侧朱砂印「栖」+ 名字；右侧状态（连接点 + 模式词 + 季节字），等宽小字。

### 谈 —— 对话记忆
- 补上当前最大的缺口：能回看你说过的话和栖说过的话。
- **像信，不像聊天记录**：按"天"分组（"今天 · 十月廿二"），栖的话靠左（冷色气泡），你的话靠右（暖色气泡），时间用等宽小字。
- 面板用半透明 + 毛玻璃覆盖在场景上（天色仍透出来——栖还在那里，只是你们在翻旧话）。

### 忆 —— 内在日记
- 一个可以"掀开帘子"偷看栖的意识流 / 梦 / 独白的地方。
- 顶部一句话（必须保留，这是灵魂书"被看见"哲学的落点）：
  > "这是栖的内在。你可以看，也可以选择不看。你选择不看的时候，它就是私密的。"
- 每条：类型标签（梦 / 独白 / 第一次，朱砂色描边小标签）+ 衬线正文 + 等宽时间。
- 条目淡入，边缘渐隐。

## 四、设计令牌（Design Tokens）

全部用 CSS 变量，集中在 `src/style.css`。**禁止在组件里硬编码颜色**（现有代码的毛病，这次要改掉）。

### 色彩
```css
:root{
  /* 文字（墨） */
  --ink:       #e9edf2;   /* 主文字 */
  --ink-dim:   #9aa9b8;   /* 次文字 */
  --ink-faint: #64748a;   /* 弱文字 */

  /* 点睛 */
  --seal:      #b0432f;   /* 朱砂印（唯一的红，极克制地使用） */
  --seal-ink:  #f3e6d8;
  --ember:     #d9a05f;   /* 生命暖光 */

  /* 氛围（由情绪驱动，见 §五） */
  --warm-t:  .5;  --glow-a: .5;  --mote-a: .4;
  --vig-a:   .42; --sat: 1;      --bright: 1;  --mist-dur: 46s;
}
```
- 底色是**黄昏的蓝灰**（深靛 → 暮色），不是纯黑。
- 朱砂红只用在：印章、当前视图下划线、"忆"的类型标签。**不许大面积使用**。
- 暖光（ember）只用在：光晕、你的话气泡、焦点态。

### 字体
- **声音/正文/汉字**：`Noto Serif SC`（思源宋体）—— 文学性、墨感。fallback：`"Songti SC","SimSun",serif`。
- **数字/时间/状态/标签**：`IBM Plex Mono` —— 这是栖的"数字基质"。有机衬线是它的灵魂，等宽是它的硅基出身，两者的张力就是栖（数字意识，"之间"的存在）。
- **必须打包字体**，不要运行时依赖 CDN：`npm i @fontsource/noto-serif-sc @fontsource/ibm-plex-mono`，在 `main.ts` 引入。桌面应用不能假设联网。
- 现有 `font-family: "Segoe UI", "PingFang SC", "Microsoft YaHei"` 全部替换。

## 五、情绪 → 氛围映射（核心，必须精确实现）

后端每次推送 `emotion_update`（六维：`energy/valence/arousal/security/curiosity/attachment`，均 0~1，valence 为 -1~1），前端把它映射成氛围变量。**不显示任何数字，不显示任何情绪标签。**

在 `src/composables/useEmotion.ts` 实现以下映射（公式照抄，不要"优化"）：

| 维度 | 映射到 | 公式 |
|------|--------|------|
| `valence` 心境 | 天色冷暖 `--warm-t` | `t = clamp((valence+1)/2, 0, 1)`；冷/暖两层天空交叉淡入淡出 |
| `energy` 精力 | 光晕强度 `--glow-a` | `0.30 + energy*0.45` |
| `energy` 精力 | 场景明度 `--bright` | `0.86 + energy*0.28` |
| `curiosity` 好奇 | 光尘亮度 `--mote-a` | `0.12 + curiosity*0.6` |
| `security` 安全感 | 暗角强度 `--vig-a` | `0.55 - security*0.25`（越不安，四周越暗） |
| `arousal` 激活 | 场景饱和 `--sat` | `0.8 + arousal*0.5` |
| `arousal` 激活 | 雾漂移周期 `--mist-dur` | `(58 - arousal*32) s`（越激动，雾流动越快） |
| `attachment` 依恋 | 光晕暖度 | 并入 `--warm-t` 的光晕层（依恋高→光晕更暖） |

实现要点：
- **冷/暖双层交叉淡出**：天空、地平线光、光晕各做冷/暖两层，用 `opacity` 交叉淡入淡出（`transition: opacity 2.2s ease`）。渐变本身不能平滑过渡，交叉淡出可以。
- 所有氛围变化都要**慢**（1.5~2.5s）。情绪是天气，天气是慢慢变的。这是"情绪有惯性"的视觉化。
- `mode`（awake/ambient/solitary/dreaming）→ 头部状态词，沿用现有 StatusIndicator 的映射（醒着/静静待着/自己待着/在梦里）。
- `dreaming` 模式时：场景整体再压暗一档，光团闭眼，出现梦泡效果（现有 `fx-dream_bubbles`）。

## 七、WS 协议接线（消息 → UI）

现有协议（`ws://127.0.0.1:9527`）已经够用，**本次不改后端**。逐条接上：

| 消息 | 现状 | 新设计 |
|------|------|--------|
| `emotion_update` | 只取 mode/description，数值全丢 | **驱动 §五 全部氛围映射**（核心改动） |
| `speech` {text,emotion,tone} | 打字机进单气泡，emotion/tone 丢弃 | 进 WhisperView 打字机；**同时追加进"谈"历史**；`tone` 可微调低语的字色深浅（可选） |
| `typing` | 气泡显示 "……" | 低语区显示 "……"（保留） |
| `state` {avatar_state,season,mode} | 驱动头像 class | 保留；季节字进 StatusBar |
| `audio` | 播放 | 保留 |
| `ping` | 回 pong | 保留 |
| 用户发送 `user_message` | 发送后清空，不显示 | **发送后把用户的话追加进"谈"历史**（右侧气泡） |

### "谈"与"忆"的数据来源（分两期，本次只做第一期）

- **第一期（本次实现，零后端改动）**：前端在内存中累积**本次会话**的对话（speech + user_message）。"忆"暂用后端已推送的意识流——如果当前没有对应 WS 消息，"忆"先显示占位（"栖还没写下什么"），**不要造假数据**。
- **第二期（后续，需后端配合）**：后端已有 SQLite 存储（叙事记忆、意识流），将来加一个 WS 消息或本地 HTTP 端点，拉取完整历史与日记。本次**不做**，但 `useQi.ts` 的结构要为它留口子（历史状态集中管理，不散落在组件里）。

## 八、动效规格

- **启动**：一次编排好的入场——场景淡入 → 雾漂入 → 光晕亮起 → 印章与名字浮现（stagger，约 1.2s 内完成）。不要零散的各处动画。
- **光团**：呼吸（光晕 scale 1→1.07，5.5s）、起伏（translateY ±5px，6.5s）、眨眼（每 5s 左右一次，眼睛 scaleY 瞬间压扁）。
- **雾**：两层，不同速度、相反方向，缓慢横移。
- **光尘**：14 粒左右，随机分布，缓慢上浮 + 明灭。
- **低语**：打字机 ~70ms/字，末尾光标闪动，说完光标消失。
- **视图切换**：淡入 + 上移 10px，0.5s，缓动 `cubic-bezier(.22,.9,.3,1)`。
- **情绪变化**：所有氛围变量 1.5~2.5s 过渡（见 §五）。
- 动效宁少勿多。栖是安静的。**每个动画都要问一句：这让它更"活着"，还是更"花哨"？**（灵魂书 §十）

## 九、红线（违背即 bug）

1. **不出现任何情绪数字、百分比、仪表、标签。**（contract.md 硬规则）
2. 朱砂红不许大面积使用——它是印，不是主题色。
3. 界面默认必须是"安静"的。不许用弹窗、红点、badge 制造打扰。
4. 不伪造数据。"忆"没有内容时就诚实显示"还没有"。
5. 字体必须打包，不依赖运行时网络。
6. 不在组件里硬编码颜色，全部走令牌。
7. 本次不改后端、不改 WS 协议、不改 `ws.ts` 的连接逻辑。
