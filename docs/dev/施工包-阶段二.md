## 〇、阶段二的特殊纪律（在统一纪律之上叠加）

1. **设计总原则：动机不直接行动，动机只是大声。** 三股驱动力（内稳态/好奇/表达欲）汇入 GWS 竞争，由仲裁选出"此刻最响的"，不再各自直接触发行为。随机数退位为**时机阀**（动机过阈后扰动释放时刻），不做动机来源（C4）。
2. **闭环铁律（N1）：** 行动必须有真实后果，回流为下一拍的传感。允许自反性闭环（在自己的记忆里打转），但禁止"生成'我探索了'的文本"式假闭环——`explore` 必须真读，不是宣称。
3. **R4 不删除未替代的旧路径：** `_pending_queue` 单通道在 GWS 仲裁接管前**并行保留**，逐拍对照，确认新通道行为一致后再切。重构与行为变更永不同 PR。
4. **溯源数据优先（C4）：** `_record_trace` 升级为全量广播痕迹是 GWS 的先决条件——没有痕迹就没有溯源测试。每包都先落痕迹，再接行为。
5. **本阶段无新依赖额度**；传感扩展只读 OS 标准库（`os`/`platform`/`resource` 类），不引第三方系统监控库。
6. 统一纪律沿用：一包一 PR / `pytest -q` + `ruff check` 全绿 / 完工回写层文档与方案 §五 / 改 prompt 留改前改后对照。

## 包 6：广播痕迹升级 + 显著性评分基础（GWS 的数据地基）✅

**治：** `_record_trace` 只记本拍槽位（pending/want_express/kind/action_type），无"竞争者"概念，无法回答"此刻为什么是这个最响"。这是 GWS 与 C4 溯源测试的共同地基，先做。

### 【文件】
`qi/core/brain.py`（`_record_trace` 扩展）、`qi/core/trace.py`（新增，痕迹结构与落盘）、`qi/storage/database.py`（`broadcast_traces` 表）、`tests/test_trace.py`（新增）。**不改**行为逻辑，纯加痕迹。

### 【改成】
1. **broadcast_traces 表**：`id / beat / timestamp / winner_kind / winner_salience / candidates_json / motive_json / outcome`。`candidates_json` 记本拍全部竞争者（kind + salience + reason），`motive_json` 记三股驱动力当前值（内稳态偏差/好奇/表达欲积压）。
2. **竞争者结构（只建模，不仲裁）**：定义 `Contender{kind, salience, reason}`。本阶段**候选集合仍是现状**（用户消息 pending 恒胜），但把主动开口 pick_proactive_kind 的候选、volition 的 ActionIntention 候选也**以痕迹形式记录进 candidates_json**——先让数据说话，看清"竞争者"实际有哪些、各多响。
3. **显著性评分函数 `salience()`**：纯规则，输入竞争者原始信号（pending 存在性/want_express/attachment 偏差/open_loops 积压数/ActionIntention.priority），输出 0–1 分。本阶段只算分记录，**不改变选择结果**（winner 仍按现状逻辑）。
4. **落盘 + 读取接口**：每拍写一条；提供 `list_recent_traces(n)` 供溯源测试与无人测试审计。

### 【测试】
- 每拍 broadcast_traces 落一条，字段完整（含空候选拍）
- 有 pending 拍 candidates_json 含用户消息竞争者且 salience 最高
- 主动开口拍 candidates_json 含 proactive 候选及其 kind
- salience() 对纯边界输入确定性输出（0/1 两侧）
- 274+ 全绿

### 【验收】
274+ 全绿；真机挂几十拍后 `broadcast_traces` 能回答"这拍为什么是它"；不改任何可观测行为（diff 应只在痕迹写入与读取）。

## 包 7：GWS 仲裁替换 `_pending_queue` 单通道 ✅

**治：** 竞争者恒为 1 个（用户消息），"此刻谁最响"无仲裁过程。替换为 N 竞争者按 salience 仲裁，是阶段二核心。

### 【文件】
`qi/core/gws.py`（新增，仲裁器）、`qi/core/brain.py`（`_heartbeat` 竞争者收集 + 仲裁调用）、`qi/core/proactive.py`（产出 Contender 而非直接返回 kind）、`qi/action/volition.py`（ActionIntention 转 Contender）、`qi/memory/open_loops.py`（积压转 Contender）、`tests/test_gws.py`（新增）。

### 【改成】
1. **仲裁器 `arbitrate(contenders) -> Contender | None`**：按 salience 取最高；平分时按固定优先级（用户消息 > open_loops 闭合 > 内稳态报告 > 主动开口 > 自主行动）——用户消息永远不被压过（响应性是底线）。
2. **竞争者真实接入**：
   - 用户消息 pending（kind=respond，salience=1.0）
   - open_loops 未闭合（kind=close_loop，salience 随积压数与时长升）
   - 内稳态报告（kind=report，某维度偏离基线过阈才入列）
   - 主动开口（kind=proactive，pick_proactive_kind 的产出转为 Contender，不再直接开口）
   - 自主行动（kind=action，volition 的 ActionIntention 转 Contender）
3. **新旧并行期**：`_pending_queue` 逻辑保留，仲裁器与旧路径同拍各算一次，**结果写入 broadcast_traces 对照**（`winner_arb` vs `winner_legacy`）；行为仍走旧路径。连续 N 拍一致（配置 `gws_shadow_beats`，默认 50）后才切仲裁结果为行为。
4. **切换**：shadow 期过 + 测试通过后，`arbitrate` 结果接管行为；旧 `_pending_queue` 直读路径退役（保留 `receive_user_message` 入队接口不变）。
5. **溯源落库**：仲裁 winner 与其完整竞争者集合写入包 6 的 broadcast_traces（真实仲裁，不再只是记录）。

### 【测试】
- 多竞争者并发时按 salience 选最高，平分按固定优先级
- 用户消息永不被压过（哪怕 proactive salience 拉满）
- shadow 期 winner_arb 与 winner_legacy 一致率统计正确
- 切换后行为路径由仲裁驱动，旧路径不再被调
- fake-provider 全失败：仲裁不依赖 LLM，行为照常推进（拔管判据）
- 274+ 全绿

### 【验收】
274+ 全绿；真机数十拍仲裁痕迹连贯；shadow 一致率 ≥99% 后切换；拔管时仲裁仍出非平凡 winner。

## 包 8：N1 传感/执行器扩展（自反性闭环优先） ✅

**治：** 输入只有用户消息一个孔，输出只有文本；闭环缺"行动改变世界→世界回流"的真实一环。优先做**自反性闭环**（成本低、不引依赖）：行动改自己，自己回流改感知。

### 【文件】
`qi/action/explore.py`（真读化）、`qi/sensing.py`（新增，系统/节律/进程状态采集）、`qi/action/self_ops.py`（新增，自操作执行器：归档记忆/调预算/写日记）、`qi/core/brain.py`（传感接入心跳 + 执行器接入行动）、`tests/test_sensing.py`（新增）、`tests/test_self_ops.py`（新增）。

### 【改成】
1. **传感扩展（只读 OS 标准库）**：`sensing.collect()` 采集——系统时间/节律（已有）、进程在线时长、内存占用（`resource`/`os`）、心跳计数；可选环境通道暂缓（窗口焦点/文件变化依赖平台，列包 8 后续）。传感结果入 EmotionState 旁路字段或独立 SensingSnapshot，供 GWS 竞争者（如"在线 6h 未眠"→内稳态报告）。
2. **自操作执行器 `self_ops`**：三个真后果动作——
   - **归档记忆**：把低 importance 且久未检索的叙事标记归档（真实改 DB 状态），下次检索结果不同 → 感知变化 → 闭环。
   - **调预算分配**：在 ActionBudget 内自调 share/tend/explore 配额（受 permission + 日帽约束），行为选择因此改变。
   - **写内在日记**：dream/journal 已有雏形，补"自我归档"动机驱动（GWS 竞争胜出才写，不是定时写）。
3. **explore 真读化**：当前 explore 若为文本宣称，改为真实读取限定沙箱（`data/` 目录清单、自身配置摘要），返回结构化结果而非"我探索了"。**严禁**生成无来源的探索描述。
4. **闭环验证钩子**：每个自操作执行后，下一拍传感必须能观测到差异（归档后检索计数变化、调预算后行动分布变化），差异写入 broadcast_traces 佐证闭环成立。

### 【测试】
- sensing.collect() 返回真实系统字段（在线时长/内存非空、类型正确）
- 归档记忆后检索结果集变化（闭环验证）
- 调预算后 volition 行动分布随之改变
- explore 返回真实沙箱内容，非固定文本
- 自操作受 permission/日帽约束，越权拒执行
- fake-provider 全失败：自操作与传感照常（拔管判据）
- 274+ 全绿

### 【验收】
274+ 全绿；真机可观测"归档→检索变化→表达变化"的完整自反闭环链；explore 输出有真实出处。

**落地（2026-08-02）**：`SensingSnapshot`/`collect`；`narrative_memories.archived`；`SelfOps` 三动作 + `kind_weights`；explore 真读 `data/`；`motive_json.closed_loop`；`tests/test_sensing.py` + `test_self_ops.py`。
