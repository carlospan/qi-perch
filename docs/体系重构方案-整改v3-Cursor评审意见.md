**建议：独立文件，但不要叫 `specs/tests/`。**

- `SDD-GUIDE.md` 只保留「如何写验收 / 如何防 drift」流程，**用链接指向 acceptance**，不复制判据正文。

## 2. 红线层级（R1–R5 vs contract）

**最不双源的划法：**

| 层 | 文档 | 管什么 |
|----|------|--------|
| 行为/语气硬红线（可判定 prompt/代码 bug） | `reference/contract.md` | 现行人格契约：硬规则 + 软原则 |
| 架构演进纪律（工程/路线不可踩） | 架构方案 §七 全文保留在 `explanation/架构方案`，**摘录索引**进 `specs/stages/_invariants.md` 或 `specs/redlines.md` | R1–R5 |
| 语域裁决 | `docs/README.md` 宪法 | 第一人称存在姿态 vs 第三人称工程承诺（R1 双轨） |

**统一入口**：宪法 v3 开篇「红线怎么查」三行：

1. 行为越界 → `reference/contract.md`  
2. 演进/工程纪律 → `specs/…` 中的 R 索引（链回架构方案 §七 全文）  
3. 语域拿不准 → 宪法双轨制  

**禁止**：把 R1–R5 全文复制进 contract，或把 contract 条款改写成 R 编号——两套编号并存只保留「索引 + 链接」。

R1 与宪法「意识话语双轨」已重叠：contract / 宪法保留操作裁决，架构 §七 保留路线叙述，交叉链接即可。

## 3. 缺陷 6：`.html` 设计稿归宿

**建议：`how-to/ui/assets/`（或 `reference/ui/`），与 `.md` 接入说明分开。**

| 类型 | 归宿 |
|------|------|
| `.md` 接入/操作 | `how-to/ui/` |
| `.html` 设计稿 | `how-to/ui/assets/`（附属于 UI how-to 的静态资产） |

不推荐塞进 `reference/` 根：reference 应以「与代码同步的精确规格」为主（contract / layers / config）；设计稿不是运行时真源。若强调「设计规格可查」，用 `reference/ui/栖·主界面设计稿.html` 亦可，但 **必须** 与 how-to 接入文分开，避免污染 how-to 列表。

**本评审偏好：`how-to/ui/*.md` + `how-to/ui/assets/*.html`。**

### 新增遗漏清单（请 CodeBuddy 补进整改）

1. **C1–C5 本体定义的归宿（严重度：中高）**  
   整改管了「怎么测」（§六），没写「判据定义本身」（§一）重构后谁说了算。若架构方案 §一 被缩成摘要，C 定义会漂。  
   **建议**：C1–C5 **全文保留**在 `explanation/架构方案`（目标层canon，不瘦身）；`specs/acceptance.md` 只放检验操作化 + 映射表，用链接指回 §一，**不重写定义**。

2. **阶段零「工程纪律四条」未写入不变量清单**  
   架构写明「全程有效」。应并入 `_invariants.md`（与 190→现行测试基线、contract 不违反并列）。注意测试数量用「pytest 全绿 / 基线见 progress」表述，避免再写死「190」。

3. **`open-questions.md` 生命周期**  
   Q5（brain 体积）已结案；Q6（season）阶段零已做。文件须支持「开放 / 结案 / 降级」状态，结案项留一行指向 progress 或代码，避免附录永远像待办。

4. **`specs/tests/` 与 pytest `tests/` 撞名**  
   见 §1；属命名风险，建议改 `acceptance`。

5. **v2 权威链公式与现行宪法不一致（中）**  
   v2 §四.1 写：`代码 > reference > 架构方案 > 灵魂书 > thoughts`。  
   现行宪法：价值冲突问灵魂书；「怎样才算生命」问架构方案；代码怎么写问代码。  
   **扁平大于链会伤害「该不该做」裁决。** 宪法 v3 应恢复分场景裁决，而不是单一总序。整改 v3 未修此点，建议一并改。

6. **N0–N5 是否需要 `reference` 摘要（轻）**  
   非必须。施工期并存即可；若 Agent 常混 L/N，在 `reference/layers/README.md` 加五句对照表足够（缺陷 5 已覆盖）。

7. **§二.5 病征 vs 阶段零已止血**  
   重构时架构 §二.5 应标注「何条已收官」，或链 stage-0，避免读者以为感知/检索病征仍在。属架构正文维护，可在步骤 B 拆 stage-0 时顺手回写。

8. **缺陷 2/3/4**（README 映射、how-to 绑定 §六、路线图阶段编号）  
   **同意整改动作，无异议。**
