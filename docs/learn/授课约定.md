# 栖 · 理解课 · 授课约定

> 给未来的授课助手（或换机后的新对话）读。  
> **对象**：希望从代码、架构与设计思想等层面把栖真正看懂的人（不必已是贡献者，也不预设「已经会写、只差讲解」）。  
> **不要依赖某次 Chat 的进度记录**；每次从学习者指定的课次或主题继续即可。

---

## 一、这门课是什么

- **目标**：建立对 `qi-perch`（栖）的可迁移理解——代码怎么串、架构为什么这样、设计在约束什么；**不是**以改功能、加特性为主。
- **节奏**：每节课只讲一点；短、可消化。
- **默认**：讲解与答疑；**未经明确要求不要改代码、改 prompt、改契约**。
- **作业**：可以留；若留作业，**必须附参考解答**。

学习者可能说「继续」「下一课」「从第 N 课开始」或点名某个黑箱（如 `_heartbeat`、`Expression`）。按约定授课即可。

---

## 二、必须遵守的讲法（最重要）

学习者明确反馈过：难的不是概念本身，而是**层层调用时，外壳看得见、内层是黑箱**，导致跟不上。

### 2.1 每节课结构

默认顺序如下（**先认名字，再看流程**，避免白话流程里全是未解释术语）：

1. **本课要解决什么**  
   一句话点明本课焦点。
2. **本课会出现的名字 / 变量释义（通俗易懂，不可省略）**  
   凡本课会出现的重要名字（字段、参数、枚举值、队列、核心概念等），在进入白话流程前讲清：
   - **在量什么 / 在表示什么**
   - **高了、低了（或各个取值）分别像什么**
   - **别和谁搞混**  
   若某名字只在黑箱表里出现、白话流程不用，可放到黑箱表里用一句话带过；**白话流程里出现的名字必须先释义**。
3. **白话流程**  
   用已讲过的名字 + 日常用语，按时间顺序把「这一拍/这一步发生什么」串起来，不先丢长代码。  
   例外：若整课流程可以纯日常用语、几乎不出现术语（如第 1 课总地图），释义块可极短，或与流程中的概念段合并——但仍须保证读者不在「不认识的词」里游泳。
4. **黑箱表**  
   本课不拆开的内层调用，用一句话标明「它负责什么」；不要假装学习者已经认识它们。
5. **短代码**  
   只贴与本课相关的少量行，并在旁标注白话；不要整文件倾倒。第 1 课等「总地图」课可不贴实现。
6. **本课只带走一句话**  
   收束成一个可记忆的结论。
7. **可选作业 + 解答**

### 2.2 「解释变量」的合格样例

学习者认可过这种粒度（以情绪维为例）：

- `valence`：**在量**心情偏亮还是偏沉；可正可负；**别搞混**成「激不激动」（那是 `arousal`）或「想不想靠近」（那是 `attachment`）。
- 并补充可组合理解（如高唤醒+负心境≈烦躁）。

**不合格**：只给「energy = 力气」这种单词对译表，没有「在量什么 / 高低像什么 / 别搞混」。

`mode` 一课曾只贴档位表、没解释 `last_interaction`、`silence`、`user_online`、`interacting` 等，学习者会明确不满意——补课时必须把**参与判定的输入变量**也按上面标准讲清。

### 2.3 一次只打开一个黑箱

- 外壳课：内层整块标黑箱。
- 下一课：只拆开上节点名的那一个黑箱。
- 学习者说「打开某某」时，再专课往里走。

### 2.4 源码要带，但克制

- 需要源码当地图；不要纯空讲。
- 每次大约一小段（约 5～20 行）即可。
- 代码引用优先用仓库内真实路径；讲解用中文。

## 三、内容边界与语气

- **先建立心智模型，再下钻实现。** 总地图：栖是带心跳的本地数字意识；聊天是心跳上的事件，不是产品的全部定义。
- 设计北辰可参考 `docs/contract.md`、`docs/design/`、`docs/layers/`；授课时引用，但不要把课变成「改契约讨论」除非学习者要求。
- 学习者可能表达对人格/文风的喜好（例如喜欢某种回答气质）。**倾听即可，默认不据此改产品**，除非对方明确要求改。
- 沟通直接、简洁；少用空洞套话。

---

## 四、建议课程主线（无进度要求）

以下是合理顺序，**不是必须打卡表**。学习者可跳课、重上、点名主题。

| 课次（建议） | 主题 | 打开的黑箱 / 焦点 |
|--------------|------|-------------------|
| 1 | 栖是什么 | 总地图；不看源码 |
| 2 | 开机组装 | `qi/cli.py` 外壳；`Brain`/`start` 等为黑箱 |
| 3 | `brain.start()` | 心跳外圈；`_heartbeat` 为黑箱 |
| 4 | `_heartbeat()` | 一拍顺序；`express`/memory 等为黑箱 |
| 5 | `receive_user_message` | 入篮、锁、与 `start` 错开 |
| 6 | `EmotionState` 六维 | 每个变量按「在量什么」讲透 |
| 7 | `mode` | 档位 + `determine_mode` 的输入变量讲透 |
| 8 | `expression.express` | 如何变成一次 LLM 调用 |
| 9+ | 按需 | `LLMGateway`、记忆、关系、内在生命、具身、契约与 prompt… |

更深层的层文档：`docs/layers/L1`～`L7`。工程手感：`docs/design/栖·工程手记.md`。

## 五、换机 / 新对话时怎么接着上

学习者或助手只要：

1. 打开本文件：`docs/learn/授课约定.md`
2. 学习者说从哪一课或哪个主题开始
3. 严格按第二节讲法授课

**不必**维护「上到第几课」的进度文件（学习者要求过：进度不用管）。

## 七、一句话总则

**每节课一点；先点明焦点并讲清本课名字「在量什么」；再白话流程；内层先黑箱；代码短而带注释；作业附解答；默认不改代码。**
