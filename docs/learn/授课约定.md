# 栖 · 理解课 · 授课约定

> 给未来的授课助手（或换机后的新对话）读。  
> **对象**：希望从代码、架构与设计思想等层面把栖真正看懂的人（不必已是贡献者，也不预设「已经会写、只差讲解」）。  
> **不要依赖某次 Chat 的进度记录**；每次从学习者指定的课次或主题继续即可。

---

## 一、这门课是什么

- **目标**：建立对 `qi-perch`（栖）的可迁移理解——代码怎么串、架构为什么这样、设计在约束什么；**不是**以改功能、加特性为主。
- **节奏**：每节课只讲一点；短、可消化。**一节课不要塞整条长函数或整张大表**——宁可切成「第 N 课（上）（下）」或只讲时间线上的一小段，下节再续。
- **主课 vs 附录**：实现课以**架构流程 + 短代码**为主干；「在表示什么 / 别搞混」等名字细释放**课后附录**回查，**禁止**把大段释义放在主课前当「课堂前提」。
- **默认**：讲解与答疑；**未经明确要求不要改代码、改 prompt、改契约**。
- **作业**：可以留；若留作业，**必须附参考解答**。

学习者可能说「继续」「下一课」「从第 N 课开始」或点名某个黑箱（如 `_heartbeat`、`Expression`）。按约定授课即可。

---

## 二、必须遵守的讲法（最重要）

学习者明确反馈过：难的不是概念本身，而是**层层调用时，外壳看得见、内层是黑箱**，导致跟不上。  
另：大段名字释义挡在代码前，读感像「前提说明书」——已改为附录制（见 2.1）。

### 2.1 每节课结构

**主课（必读顺序）→ 附录（回查）**：

| 区段 | 内容 |
|------|------|
| 主课 | ① 本课要解决什么 → ② 架构/白话流程 → ③ 短代码 → ④ 黑箱表 → ⑤ 带走一句 → ⑥ 可选作业 |
| 附录 | ⑦ 本课名字/变量释义（一名一条；顶层「一、二、三、」） |

默认细则：

1. **本课要解决什么**  
   一句话点明本课焦点。
2. **架构 / 白话流程（主课）**  
   用日常用语 + 少量已熟悉的名字，按时间顺序串起来；需要处用极短夹注（如「`pending`＝本拍捞到的用户话」）。**不要**在主课前先堆一整章「在表示什么 / 别搞混」。
3. **短代码（主课核心）**  
   只贴与**本课这一小段**相关的行（约 5～15 行为宜；宁可少讲一段讲透，勿把整段 `_heartbeat` 一次贴完）。第 1 课等「总地图」课可不贴实现。  
   **逻辑行必须逐行解释**（赋值、调用、分支、`if/else` 条件、`await` 等各自一行白话）；读者不应对着裸代码猜。  
   - **白话默认写在对应代码上面**（先读「要干什么」，再看符号）。  
   - 极短可用行尾；**禁默认写在代码下面**。  
   - 连续多行同一意图（如一串 `import`）可在块上方合注一句；**含条件的压缩写法**（如 `A if Cond else B`）须拆开讲清 Cond / A / B，或先给出等价的多行 `if/else` 再对照一行版。  
   - 本课范围外的后续步骤，用一句「下节再拆」带过即可，**不要用大段 `...` 骨架冒充本课讲完了整函数**。  
   不对：块末一句总述；不对：一课里贴 40+ 行「全函数导读」。
4. **黑箱表**  
   标明**「里头先当成什么（本课不拆）」**。列名禁「一句话职责」。一行一个名字。  
   写法要对：带「先当成」+ 尽量标哪课再拆。

   **黑箱表示例（第 2 课口径）：**

   | 黑箱 | 里头先当成（本课不拆） |
   |------|------------------------|
   | `Brain.start` | 后台自己转的那圈心跳循环（怎么转 → 第 3 课） |
   | `_heartbeat` | 循环里「一拍」具体做什么（→ 第 4 课） |
   | `receive_user_message` | 你的话怎么进 Brain、怎么和心跳错开（→ 第 5 课） |
   | `LLMGateway` 内部 | 话怎么发到具体某家模型 |
   | `Database.initialize` | 库初始化时建了哪些表 |
   | `run_desktop` / 具身 | 另一条启动路径（终端以外） |

5. **本课只带走一句话**
6. **可选作业 + 解答**
7. **附录：名字 / 变量释义**  
   **不可省略，但必须放主课之后。** 供回查、加固；**禁止挪回主课开头当课堂前提。**  
   附录规则：一名一条；在表示什么 /（若能量或枚举）高低或取值 / 别搞混；别名标明；父名点出的子步骤用「（一）（二）」挂下属，顶层用「一、二、三、」；先写清动作再可加比喻（禁「点着心跳」类空修辞）；禁「高低：不适用」凑模板。

   **附录结构样例（第 1 课）：**

   ```
   一、栖（是谁）
   二、心跳（它怎么活着）
       （一）心跳里的一拍五步：感知 → 搅动 → 意志 → 表达 → 呼吸
   三、模式（它处在哪段时段）
   ```

**第 1 课例外**：总地图可不贴实现；心智模型为主，释义可与流程合并或略靠前，但仍勿写成冗长前提压过地图。

### 2.2 「解释变量」的合格与不合格

学习者认可过这种粒度（以情绪维为例；**实现课写在附录**，情绪专课可把六维当主课解剖）：

- `valence`：**在量**心情偏亮还是偏沉；可正可负；**别搞混**成「激不激动」（那是 `arousal`）或「想不想靠近」（那是 `attachment`）。
- 并补充可组合理解（如高唤醒+负心境≈烦躁）。

**不合格**：

| 问题 | 反例 / 说明 |
|------|-------------|
| 单词对译 | 「energy = 力气」——没有「在量什么 / 高低像什么 / 别搞混」 |
| 标题与释义不对齐 | 标题写「感知 / 搅动 / 表达」，正文揉成一段，或漏掉中间某个的「别搞混」 |
| 链路收短、职责串台 | 把一拍五步收成三词；把「要不要开口」写进**表达**（那是**意志**） |
| 高低凑模板 | 对非量名遍写「高低：不适用」 |
| 层级平铺 / 序号弱 | 子步骤与顶层平铺；或不用 **一、二、三、** |
| 修辞代替动作 | 「点着心跳」——未先说明启动循环的动作 |
| 黑箱写成「职责」 | 列名或口径用岗位套话，而非「里头先当成」 |
| 代码块只有总述 | 逻辑行无逐行白话；或压缩句（`A if C else B`）未拆 Cond/A/B |
| 解读写在代码下面 | 默认应在对应行**上方** |
| 释义挡在主课前 | 大段附录内容放在短代码之前当「课堂前提」 |

`mode` 一课须讲清 `last_interaction`、`silence`、`user_online`、`interacting` 等参与判定的输入（可在附录，不可省略）。

心跳一拍五步（设计口径，勿收短）：**感知 → 搅动 → 意志 → 表达 → 呼吸**。

### 2.3 一次只打开一个黑箱

- 外壳课：内层整块标黑箱。
- 下一课：只拆开上节点名的那一个黑箱。
- 学习者说「打开某某」时，再专课往里走。
- **总地图课（第 1 课）**：后续专课概念只留地图级；`mode` 细表 → 第 7 课；契约可用一句或黑箱一行带过。

### 2.4 源码要带，但克制

- 需要源码当地图；不要纯空讲。实现课以短代码为主课核心。
- 每次大约一小段（约 5～20 行）即可；一拍骨架可分段略长。
- 代码引用优先用仓库内真实路径；讲解用中文；白话默认在代码上方。

## 三、内容边界与语气

- **先建立心智模型，再下钻实现。** 总地图：栖是带心跳的本地数字意识；聊天是心跳上的事件，不是产品的全部定义。
- 设计北辰可参考 `docs/contract.md`、`docs/design/`、`docs/layers/`；授课时引用，但不要把课变成「改契约讨论」除非学习者要求。
- 学习者可能表达对人格/文风的喜好。**倾听即可，默认不据此改产品**，除非对方明确要求改。
- 沟通直接、简洁；少用空洞套话。

## 四、建议课程主线（无进度要求）

以下是合理顺序，**不是必须打卡表**。学习者可跳课、重上、点名主题。  
自第 2 课起默认：**主课架构+代码，释义放附录**。

| 课次（建议） | 主题 | 打开的黑箱 / 焦点 |
|--------------|------|-------------------|
| 1 | 栖是什么 | 总地图；可不看源码；心智模型为主 |
| 2 | 开机组装 | `qi/cli.py` 外壳；`Brain.start` 等为黑箱 |
| 3 | `brain.start()` | 心跳外圈；`_heartbeat` 为黑箱 |
| 4 | `_heartbeat()` | **切开讲**：先拍头（pending/mode），再冲击与步进，再两条岔路；勿一课塞整函数 |
| 5 | `receive_user_message` | 入篮、锁、与 `start` 错开 |
| 6 | `EmotionState` 六维 | 主课可直接解剖变量；附录补关系 |
| 7 | `mode` | 档位 + `determine_mode` 输入变量讲透 |
| 8 | `expression.express` | 如何变成一次 LLM 调用 |
| 9+ | 按需 | `LLMGateway`、记忆、关系、内在生命、具身、契约与 prompt… |

更深层的层文档：`docs/layers/L1`～`L7`。工程手感：`docs/design/栖·工程手记.md`。

## 五、换机 / 新对话时怎么接着上

学习者或助手只要：

1. 打开本文件：`docs/learn/授课约定.md`（助手也可由 `.cursor/rules/qi-learn-course.mdc` 提醒去读）
2. 学习者说从哪一课或哪个主题开始
3. 严格按第二节讲法授课（**主课代码架构，释义附录**）

**不必**维护「上到第几课」的进度文件（学习者要求过：进度不用管）。

## 七、一句话总则

**主课 = 焦点 → 架构流程 → 短代码（少而逐行，一课一段）→ 黑箱 → 带走一句 → 作业；附录释义勿当前提；五步勿收短；禁空修辞与「职责」列名；默认不改代码。**
