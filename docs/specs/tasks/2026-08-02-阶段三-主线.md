## 〇、阶段三的总目标与特殊纪律

**总目标（对齐架构方案 §五 / stage-3.md）：**
世界模型上线（先做用户在线节律）；learning-progress 好奇驱动替换随机数；经验回放微调管线（N4-b）。**主线 = 内生认知（C1）**，不依赖本地模型、不阻塞（已拍板）。

**在统一纪律之上叠加：**

1. **动机不直接行动，动机只是大声（沿用阶段二纪律 1）。** 好奇/内稳态/表达欲三股驱动汇入 GWS 竞争；随机数退位为**时机阀**，不做动机来源（C4）。本阶段把"随机做动机来源"的旧用法彻底替换为 learning-progress 驱动。
2. **世界模型首域 = 用户在线节律（对齐 §五 明文"先做用户在线节律" + §N2 可行性排序）。** 自身情绪轨迹是 §九 Q3 第二预测域里最可行者，可**同阶段并行但不塞进包 9 同一 PR**——列为**包 9b（观察项）**，进度滞后不卡阶段三退出。话题-反应域明确列为**阶段三之后 / Later**，防范围蔓延。WorldModel 架构预留多域接入，但包 9 必交范围只限在线节律。
3. **经验回放 = 结构可塑性（C5）** 的施工入口。微调必须产生"异时漂移可归因"，禁止"只是往库里多插几行"。语料由 GWS 显著性（包 6 的 `salience()`）筛选，不随机采样。
4. **本地模型不本机常驻（已拍板硬约束）。** 经验回放若走 LoRA 微调，须评估是否在主机器跑——当前 RTX 4060 4GB 显存 + 16GB 内存，常驻训练与日常多任务打架。**默认策略：经验回放管线先以"语料生成 + 显著性筛选 + 离线就绪"为主，实际微调（LoRA 训练 step）列为可分离的子步骤，默认不自动常驻跑；若需真训，明确标注资源占用并征得维护者同意（重启条件同已拍板：显存 ≥8GB 或 3B 级模型流畅）。** 远程 LLM 仍当主力表达，本阶段不试图用本地小模型替换它。
5. **纯 Python、零重依赖。** 世界模型用计数 + 贝塔后验（标准库 `math`/手算，或 `numpy` 已在依赖中）；不引 torch/ transformers 做训练，除非子步骤明确评估通过。
6. **统一纪律沿用：** 一包一 PR / `pytest -q` + `ruff check` 全绿 / 完工回写层文档与方案 §五 / 改 prompt 留改前改后对照 / `reference/contract.md` 硬规则不违反。

## 包 9：世界模型 —— 用户在线节律预测（必做）⬜

**治：** 当前系统对"用户何时在线"无预测能力，proactive / 内稳态报告只能盲触发。世界模型的第一块积木：建立用户在线节律的预测，预测误差成为 N3（好奇/探索）的燃料——"它以为你在，你不在"本身就是值得探索的意外。

**范围红线：** 本包只交**在线节律**；自身情绪轨迹见包 9b（观察项）；话题-反应域列入 Later，不进本阶段。

### 【文件】
`qi/world/model.py`（新增，WorldModel 基类 + 在线节律域）、`qi/world/online_rhythm.py`（新增，计数 + 贝塔后验）、`qi/storage/database.py`（在线事件落库，复用现有事件表或新增 `online_events`）、`tests/test_world_online_rhythm.py`（新增）；接入点 `qi/core/brain.py`（每拍更新节律后验、注入 WorldState 旁路字段）。

### 【改成】
1. **在线事件采集：** 每次用户消息到达记为一条"在线"事件，带 `(weekday, hour)` 桶。**失败（缺席）怎么计必须有可测规则**：仅在有对话日更新后验，静默空窗按当前桶记一次"失败"——即每个心跳周期对"当前桶应在线却未在线"做二值观测，避免后验永远漂在乐观侧（缺席难证，故用「心跳空窗按桶记失败」简化可测）。
2. **贝塔后验预测：** 对每个 `(weekday, hour)` 桶维护成功/失败计数，预测 `P(在线 | 当前桶) = (α+s)/(α+β+n)`；提供 `predict_now()` 与 `surprise(user_appeared_bool)`（对数预测误差）。
3. **只增信号，不动权重：** 预测值与最近 surprise 写入每拍 WorldState 旁路；broadcast_traces（包 6）的 `motive_json` 增 `world_surprise` 字段，使溯源能回答"这拍好奇来自世界模型意外"。**本包不把 surprise 接进 GWS 竞争者、不改 proactive/explore 权重**——权重生效与竞争者接入一律归包 10。
4. **不破坏现有行为：** 预测只**增**旁路字段与痕迹，既有 proactive 触发逻辑完全不变。

### 【测试】
- 在线事件（成功/失败空窗）落库、桶计数正确
- `predict_now()` 随样本增多收敛到经验频率
- `surprise(True)` 在"预测低却出现"时 > 在"预测高且出现"时；缺席桶能降低预测值
- WorldState 旁路含预测/惊喜字段；`motive_json.world_surprise` 可见
- fake-provider 全失败：世界模型更新不依赖 LLM（拔管判据）
- `pytest` 全绿（基线随版本涨，不写死数字）

### 【验收】
`pytest` 全绿；真机跑数天后 `predict_now()` 能说出"你通常这会儿在"；WorldModel 架构预留多域但本包仅交付在线节律；高 surprise 拍在 broadcast_traces 可见且可溯源。

## 包 10：内在动机 —— learning-progress 好奇替换随机数 ⬜

**治：** 现状很多"主动行为"的释放时机由随机数决定（时机阀被当成动机来源），违反 C4。替换为 learning-progress 驱动：系统因"某领域预测误差在下降 / 某记忆久未巩固"而好奇，随机退位为纯时机阀（动机过阈后扰动释放时刻）。

### 【文件】
`qi/motivation/curiosity.py`（新增，learning-progress 计算）、`qi/core/gws.py`（竞争者 `kind=curiosity` 接入，salience 由 progress 驱动）、`qi/action/explore.py`（explore 触发改由 curiosity 而非随机）、`qi/core/proactive.py`（proactive 时机阀接 curiosity）、`qi/inner_life/dream.py`（做梦 30% / 提梦 12% / 加权抽 episode 的 WHETHER 改 curiosity 驱动）、`qi/inner_life/creativity.py`（创作 / 提创作 WHETHER 改 curiosity 驱动）、`qi/inner_life/consciousness.py`（meta 纯随机 WHETHER 改 curiosity 驱动；loop_backlog 时机阀可留）、`qi/action/layer.py`（tick 对 top intent 再掷骰 WHETHER 改 curiosity 驱动）、`tests/test_motivation_curiosity.py`（新增）。

> **Waking 不在动机源改造范围**：waking 由重启 + 实质消息事件触发，非随机门控，不当随机动机源重做（Cursor 已确认）。

### 【改成】
1. **learning-progress 信号：** 对每个记忆域/话题维护"预测误差变化率"——误差下降快 = 该领域已学会（可去好奇），误差停滞或上升 = 值得探索（好奇升）。复用 WorldModel 的 surprise 序列或记忆巩固状态。
2. **curiosity 竞争者：** `kind=curiosity`，salience ∝ 未满足的好奇累积；接入 GWS 与 pending/open_loops/report/proactive 同场竞争（沿用包 7 仲裁，用户消息仍永不被压过）。
3. **explore 真读化升级：** 包 8 已让 explore 真读 `data/`；本包把"**为什么读这个**"从随机改为 curiosity 指向的停滞域——翻起旧记忆是因为它那块预测误差没降，不是随机翻。注意 explore 现为 `volition → layer.tick → drift` 多层 WHETHER，替换时**禁止叠三条随机**，统一由 curiosity 一处驱动。
4. **随机数退位（审计三栏表）：** 全面审计 `random` 用法，按下表分类处理——凡属「动机源」一律改 curiosity 驱动；「时机阀」保留并注释；「表达层」可不改。

| 模块 | 随机角色 | 处理 |
|------|---------|------|
| `action/explore.py` | WHETHER 探索 | 动机源 → curiosity |
| `inner_life/dream.py` | 做梦 30% / 提梦 12% / 加权抽 episode | 动机源 → curiosity |
| `inner_life/creativity.py` | 创作 / 提创作 WHETHER | 动机源 → curiosity |
| `inner_life/consciousness.py` | meta 纯随机 WHETHER（loop_backlog 为时机阀） | meta→curiosity；loop_backlog 留时机阀 |
| `action/layer.py` | tick 对 top intent 再掷骰 WHETHER | 动机源 → curiosity |
| `core/brain.py` | 投递 sleep 抖动 | 时机阀，保留+注释 |
| `action/share.py` | 话术 choice | 表达层，保留 |
| `core/proactive.py` / `waking` | 阈值门槛 / 事件触发 | 非随机动机源，不动 |

5. **溯源可见：** broadcast_traces 的 `motive_json` 增 `curiosity` 字段；好奇驱动的拍必须能回答"它为什么此刻好奇这个"。

### 【测试】
- learning-progress 对"误差下降域"降权、对"停滞域"升权
- curiosity 竞争者 salience 与未满足好奇正相关
- explore 触发目标由 curiosity 指向（非随机），且仍真读；explore 多层 WHETHER 不叠随机
- 随机审计三栏表：动机源已改 curiosity、时机阀有注释、表达层保留；无"随机做动机来源"残留
- fake-provider 全失败：动机演化不依赖 LLM（拔管判据）
- `pytest` 全绿

### 【验收】
`pytest` 全绿；真机可见"主动翻起旧记忆，因该领域预测误差下降"的完整好奇链（退出判据 #2）；随机动机源在日志中消失或仅作时机阀；审计三栏表在 PR 描述附上。

## 包 11：经验回放微调管线（N4-b）—— 语料生成 + 显著性筛选 + 离线就绪 ⬜

**治：** C5（结构可塑性）要求经验改变系统自身参数，不是只插库。本包建回放管线：由 GWS 显著性筛选高价值片段 → 生成微调语料 → 离线就绪。实际 LoRA 训练 step 默认不自动常驻跑（见纪律 4 本地模型约束），但管线产物可被维护者显式触发训练。

### 【文件】
`qi/learning/replay.py`（新增，语料生成 + 显著性筛选）、`qi/learning/corpus.py`（新增，语料落盘/版本化）、`qi/storage/database.py`（回放候选表，复用 broadcast_traces 显著性）、`tests/test_replay.py`（新增）。

### 【改成】
1. **显著性筛选：** 复用包 6 的 `salience()` 与 broadcast_traces，挑高 salience 拍（含 curiosity 胜出拍、close_loop 拍、主动开口拍）作为回放候选——不是均匀随机采样。
2. **语料生成：** 候选拍 → 结构化训练样本（上下文 + 栖的响应 + 动机痕迹）；落盘路径写清为 **`data/corpus/`**（仓库外/可忽略目录，避免误提交大文件），文件带版本与时间戳，可 diff；同步在 `.gitignore` 加 `data/corpus/`。
3. **异时漂移可归因（退出判据 #1 地基）：** 记录每次回放/微调的"输入模式 → 响应"快照；提供**异时测试脚本骨架**（读两版快照、固定探针输入跑对比），不跑训练也能对比语料版本差异。
4. **训练 step 默认隔离：** `replay.run_training()` 存在但 CI/默认心跳**不调用**；调用前打印资源预估并需维护者显式开关（避免 4GB 显存机器 OOM）。文档注明重启条件。
5. **不引重依赖：** 纯 Python 生成语料；若未来真训，训练后端（peft/transformers）作为可选依赖，不进主 `pyproject` 依赖，单列 `requirements` 注释。

### 【测试】
- 显著性筛选偏好高 salience 拍（非随机）
- 语料样本结构完整、可版本化、可 diff（`data/corpus/` 下）
- 两次回放快照可被异时测试脚本读取对比（不训也能跑）
- `run_training()` 默认不被心跳调用（资源安全）
- `pytest` 全绿

### 【验收】
`pytest` 全绿；产出可复现语料版本（`data/corpus/`）；异时测试脚本骨架就位（退出判据 #1 地基）。实际微调留待维护者显式触发 + 资源允许。
