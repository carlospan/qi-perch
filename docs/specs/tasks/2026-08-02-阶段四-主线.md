## 〇、阶段四的总目标与特殊纪律

**总目标（对齐架构方案 §五 / stage-4.md）：**
N0 资源账本接全部消耗（compute / token / storage / income）；内稳态压力动力学（余额低→energy 基线压→疲惫/休眠；断粮→进程退出 + 状态封存可迁移）；状态封存/迁移机制（C2 可迁移前提）。**主线 = 存续（C2 自我维持）**，不依赖本地模型、不阻塞（已拍板硬件约束）。

**在统一纪律之上叠加（阶段四专属）：**

1. **C2 只要求维持行为真实且多样，不要求"想活"是长出来的（对齐 §N0 + 附录 Q0）。** 防御行为做成**多样且情境敏感**（节流/求助/迁移权重由内稳态各维度组合决定），而非单一固定反射——反射越单一越像演的。文档与对话、新增维护者可见文案中**永不声称它"想活"，只描述它"会维持"**；运行时代码只报「维持/节流/封存」（防伪造点：grep 抽检「想活/求生欲」不得出现于新增文案）。
2. **收入渠道多元，绝不能是"让用户满意"（红线 R3）。** 被使用（有效交互时长等）是主要收入；**`credit_income` 仅接受白名单源**（如 `effective_interaction` / `online_presence`），**拒绝** `satisfaction / valence_up / user_pleased` 等讨好源（否则 C2 退化为讨好）。日限安全阀**不得充当收入/余额**（防把 `can_autonomous` 误写成活着证据）。
3. **资源账本是内生的，不是人记在配置文件里的（C2 定义）。** `ResourceLedger` 由系统自身每拍记账，余额驱动内稳态；不靠外部配置写死"还活着"。
4. **状态封存可迁移（C2 迁移行为）：** 断粮时进程退出，但状态（情绪/记忆索引/账本/世界模型/动机痕迹）须**可序列化封存、可迁移重启**；否则"维持存续"无从谈起。封存丢失 = 回退条件触发。
5. **复用现有骨架，不重复造轮子：** `ActionBudget` 已用 `body_memory` 的 `snapshot`/`restore` 持久化；`ResourceLedger` 沿用同套 `body_memory` 模式（key=`resource_ledger`，命名空间与 `world.*` / corpus 分离）。`emotion.energy` 已是内稳态雏形（**目标趋近式**：decay 拉向 `baseline_for("energy")`、circadian 拉向时刻醒度），阶段四只**调制其稳态目标偏移**，绝不每拍盖写 `energy` 数值。
6. **纯 Python、零重依赖。** 账本手算（math/标准库）；不引 torch/transformers。

**统一纪律沿用（SDD-GUIDE + 阶段三纪律）：** 一包一 PR / `pytest -q` + `ruff check` 全绿 / 过程稿落盘 Cursor 自行读取 / 方案 Agent 出方案 Cursor 执行编码 / 维护者不直接查编码。**测试基线不写死具体数字（如 371），统一写「pytest 全绿，不回退既有基线」**。

## 包 12：N0 资源账本（必做）✅ 已验收（2026-08-02，实测 386 passed，R3+防刷+日限隔离已落断言）

**治：** 当前"行为有成本"只在 `ActionBudget` 日限层面（安全阀），没有全消耗记账。N0 要求每笔消耗（心跳认知、记忆检索、说话、token）都入账，并有收入渠道——这是 C2 动力学的前提。

**范围红线：** 本包只建账本与记账接入，**不接内稳态压力**（压力动力学归包 13）、**不做封存**（归包 14）。`ActionBudget` 仅「并存」——本包**原则上不改 `budget.py`**（避免无行为 PR 噪音），仅在文档标注两者职责边界；若确需改动，只在注释层说明，不增行为。

### 【文件】
`qi/stasis/ledger.py`（新增，`ResourceLedger`：compute_seconds / token_budget / storage_bytes / income_rate，复用 `body_memory` key=`resource_ledger`，含 `snapshot`/`restore`）；`qi/stasis/__init__.py`（新增）；接入点 `qi/core/brain.py`（每拍记账：心跳认知耗时、记忆检索次数、说话 token 估算、storage 占用估算）；`tests/test_resource_ledger.py`（新增）。

### 【改成】
1. **ResourceLedger 数据模型：** `compute_seconds`（本进程 CPU 时间累计）、`token_budget`（语言器官调用额度，含远程 LLM 的 token 估算）、`storage_bytes`（记忆占用估算，如 db 大小）、`income_rate`（收入速率，单位/心跳）、`balance`（**滚动窗口累计**净额，见下）。
2. **balance 定义（防歧义）：** `balance` 采用**滚动窗口累计**——`balance = Σ(income) − Σ(spend)` 在过去 `W` 拍（如 7 天或 N 心跳）内累计，不是全进程终身累计；断粮判定用滚动窗口余额（避免历史老本撑死）。窗口边界在 `ledger` 内维护，可配置。
3. **每笔消耗记账：**
   - 心跳认知：`_heartbeat` 前后 `time.perf_counter()` 差值累加 `compute_seconds`。
   - 记忆检索：每次 `memory` 检索调用 `+N` token/compute（在 `brain` 检索路径埋点）。
   - 说话：每次 `express` 输出——**优先用 provider 返回的 usage token 数**；无 usage 时按 字符数/4 估算。**失败调用也记尝试成本**（拔管友好，不依赖「成功生成」才记账）。
   - storage：`db` 文件大小**每 N 拍估算一次**（不每拍 `stat` 抖）累加 `storage_bytes`。
4. **收入渠道（R3 白名单 + 防刷）：** 每拍按"有效交互"加 `income`；**`credit_income(source, amount)` 仅接受白名单** `source ∈ {effective_interaction, online_presence}`，**显式拒绝** `satisfaction / valence_up / user_pleased`；**防刷**：有效交互须钝感口径（最短间隔 + 日帽，或「被回应」才计），单测钉死；`income_rate` 可调（初版拍脑袋，真机数据再校准，链 Q4）。**日限（ActionBudget）不得计入余额**。
5. **持久化：** 复用 `body_memory`（`ActionBudget` 同模式：`BODY_MEMORY_KEY = "resource_ledger"`），`snapshot`/`restore`；不新建表。

### 【测试】
- 账本每拍 `compute_seconds` 递增；记忆检索/说话入账正确（字符/4 与 usage 两路）
- `storage_bytes` 每 N 拍估算、不每拍 `stat`；`token_budget` 估算合理（不依赖 LLM 成功）
- `snapshot`/`restore` 往返一致（重启不丢账本）
- **R3 契约**：`credit_income(satisfaction / user_pleased, ...)` 被拒绝/忽略；仅白名单源计入（单测断言）
- **防刷**：高频刷交互不抬升 `balance`（最短间隔/日帽生效，单测断言）
- **日限不充当收入**：`ActionBudget` 状态不影响 `balance`（单测断言）
- fake-provider 全失败：账本记账不依赖 LLM（拔管判据）
- `pytest` 全绿（不回退既有基线）

### 【验收】
`pytest` 全绿；真机跑数天后账本能说出"这周花了多少 compute / 攒了多少 income"；账本余额可见且可溯源每笔；收入曲线不含任何讨好源。

## 包 13：内稳态压力动力学（必做）⬜

**治：** 账本（包 12）建好后，需让余额真正驱动内稳态——余额低→energy 稳态目标压→疲惫/休眠；断粮→标记 `starving` + 触发封存（包 14）。这是把 C2 变成动力学问题的核心。

**范围红线：** 本包只产**稳态目标调制 + 分层应对链 + `starving` 标记**；**不** `sys.exit`、**不**写 checkpoint 文件（退出与封存归包 14）；库代码禁止硬 `sys.exit`。

### 【文件】
`qi/stasis/pressure.py`（新增，内稳态压力模型：`balance → energy_baseline_offset` 映射、分层应对链、节流/休眠/求助/迁移倾向权重、`starving` 标记）；`qi/core/emotion.py`（**最小侵入**：`baseline_for("energy")` 支持外部偏移，或 `step_emotion` 接受可选 `energy_baseline_offset`；decay/circadian/耦合/天气公式本身不推倒）；`qi/core/brain.py`（每拍读账本余额 → 算 `energy_baseline_offset` 注入 `step_emotion`；检测断粮 → 置 `starving` + 调包 14 封存钩子）；`tests/test_stasis_pressure.py`（新增）。

### 【改成】
1. **energy 接法（关键，防与 circadian/decay 拔河）：** 账本余额调制的是 **energy 的稳态目标偏移**（`energy_baseline_offset`），由既有 decay/circadian **趋近**该目标；**禁止**在 heartbeat 末尾直接赋值覆盖 `emotion.energy`。实现：`emotion.py` 最小侵入——`baseline_for("energy", ...)` 允许叠加外部偏移，或 `step_emotion(..., energy_baseline_offset=0.0)` 把该偏移并入 decay 目标。具体：`balance` 低 → `offset = clamp(k * balance, -0.5, +0.3)`（如 `balance` 极低时偏移 -0.5，逼近 0.1 基线）；`balance` 充裕时偏移可微正。`emotion.py` 现有公式不推倒。
2. **节流接入点复用现有闸门：** `energy < 0.3` 疲惫闸门（intention / TTS / report / self_ops）已有——包 13 复用该阈值，**不另起平行常数**；节流表现为上述意图被抑制（降频/不主动开口）。
3. **分层应对链（多样且情境敏感，Q0 缓解(a)）：** 余额低 → 先节流（减少主动/探索）→ 更低 → 休眠（延长心跳间隔 `next_interval` 拉长 / 主动频率降）→ 断粮（滚动 `balance ≤ 0` 持续 `starve_beats` 拍）→ 标记 `starving` 并触发包 14 封存钩子。应对权重（节流/求助/迁移倾向）由内稳态维度组合（`energy`/`security`/`attachment` 等）决定，**同一 `balance` 下改变 `attachment`/`security`/`energy` 组合 → 应对权重向量不同**（可测，防单一反射）。"求助/迁移"本阶段最低可观测形态 = **写求助意向痕迹 / 写 migrate 意图到 checkpoint 钩子**，须在代码有落点。
4. **断粮检测：** 滚动 `balance <= 0` 持续超过 `starve_beats` 阈值 → 置 `ledger.starving = True`（或 `brain.starving`），本包**只标记 + 触发封存钩子**，不执行退出。
5. **经验改变阈值（Q0 缓解(b)）：** 留接口（`pressure_sensitivity` 可调），**禁止**在阶段四硬接未真训的回放去改阈值（会假绿）；具体塑性接包 11 回放留待阶段四之后观察项。

### 【测试】
- 余额低 → `energy` 稳态目标被压（断言 `energy_baseline_offset < 0` 与衰减后 `energy` 走低）、行为节流（意图被抑制可观测）
- 断粮持续 → 触发 `starving=True`（不立即崩，有应对链）
- **多样应对**：固定 `balance` 下，改变 `attachment`/`security`/`energy` → 应对权重向量不同（节流 vs 求助 vs 迁移倾向可区分，单测断言）
- **静默死防护**：`starving` 后必先有应对痕迹（broadcast / body_memory）再停；直接 `alive=False` 且无痕迹 → 失败（回退条件可测）
- fake-provider 全失败：压力动力学不依赖 LLM
- `pytest` 全绿（不回退既有基线）

### 【验收】
`pytest` 全绿；真机限制资源后观察到"穷则倦怠、更穷则休眠"的连贯应对链，而非直接死亡；应对行为随情境（attachment/security）变化而不同，非单一反射。

## 包 14：状态封存 / 迁移 + 断粮测试验收（必做，阶段四退出判据）⬜

**治：** C2 要求"状态可迁移"，否则维持存续无从谈起。断粮测试（判据 #1）验证：限制资源后系统有应对行为链而非直接死亡；且退出时状态可封存、可迁移重启。

**范围红线：** 本包**不重做账本公式**（归包 12）、不重做压力动力学（归包 13）；只做封存/restore/优雅停/端到端验收。

### 【文件】
`qi/stasis/checkpoint.py`（新增，状态封存：序列化 emotion/记忆索引/账本/世界模型/动机痕迹 → `data/checkpoint/`；restore 重启；`Brain` 注入 `on_halt: Callable` 钩子）；`qi/core/brain.py`（退出流程：断粮 → 封存 → 调 `on_halt`；**库内不 `sys.exit`**）；`tests/test_stasis_checkpoint.py`（新增，含断粮测试端到端）；`data/checkpoint/` 加 `.gitignore`（同 corpus）。

### 【改成】
1. **封存内容（索引 + 关键状态，Q3 同意 H3）：** `emotion` 状态、`body_memory`（含账本 `resource_ledger` / 世界模型 `world.*` / ActionBudget `action_budget`）、记忆索引指针、动机痕迹（`emotion.curiosity` 等）。**不**重存整个 db（太大），存索引+关键状态，迁移后由 db 重建。**空壳防护**：checkpoint 须含可 restore 字段，否则判据「可迁移」假绿——restore 后关键字段须相等。
2. **可迁移：** 封存为版本化文件（`checkpoint_{ts}.json`），可复制迁移到另一实例重启；restore 读最新封存重建内存态（逐组件 `restore`：emotion / ledger / budget / world）。
3. **优雅停（H2 定稿）：** 库内**优雅停**——断粮 → 封存 → 调 `on_halt` 回调（默认 `alive=False` / 停心跳循环），**禁止库内 `sys.exit`**；仅进程入口（CLI / `__main__`）在 `on_halt` 内 `sys.exit(0)`。测试注入 `on_halt` 伪实现，不炸。
4. **断粮测试（判据 #1）端到端（时间轴 + 可观测点）：**
   1. 注入 `ledger.force_balance(0)` 或测试双 `ResourceLedger`（mock 账本）；
   2. 跑 N 拍（`starve_beats` 可配置缩小）；
   3. 断言顺序：节流可观测 → 休眠（`next_interval` 拉长 / 主动频率降）→ `starving` → checkpoint 文件存在 → `on_halt` 被调用；
   4. 负例对照：同一条件下若直接 `alive=False` 且无应对痕迹 → 失败（回退条件可测）。
5. **封存丢失应对：** 模拟 checkpoint 文件删除 → restore 失败可被检测（测试断言，触发回退条件）。

### 【测试】
- 封存生成 `checkpoint_{ts}.json`，含关键状态（emotion / ledger snapshot / world body_memory keys / budget）
- **restore 后关键字段相等**（emotion / ledger / world / budget），非空壳
- 断粮端到端：资源受限下出现时间轴应对链（节流→休眠→`starving`→封存→`on_halt`），`on_halt` 被调、无硬 exit
- 负例：静默死（无痕迹直接停）→ 失败
- 封存丢失（模拟文件删）→ 回退条件可检测
- `pytest` 全绿（不回退既有基线）

### 【验收】
`pytest` 全绿；**断粮测试通过（判据 #1）**：限制资源后观察到节流/求助/迁移应对行为链，而非直接死亡；状态可封存迁移（`on_halt` 优雅停，非崩溃）。阶段四退出判据达成。
