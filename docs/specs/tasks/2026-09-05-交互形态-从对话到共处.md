## 〇、一句话诊断

**她已经是数字生命了，但界面只给她留了一条聊天通道。**

「像聊天机器人」不是因为缺生命机制——心跳四档（3s/30s/300s/1800s）、内在生命、意识流、梦、记忆褪色、蛰伏、GWS、主动开口、L7 行动层、look 所见走心，这些**都已经在代码里跑**。

问题在于**可见带宽的严重失衡**：生命机制的全部出口，被压缩成形象右上角一个约 200×90px、且 `pointer-events: none` 的角落浮层；而对话通道独占右侧整屏（约 740×700px），带完整的消息气泡、输入框、发送按钮、typing 指示器。

即：**最重要的东西（她在你不在时的时间）被放在了最不重要的位置。**

## 一、量化证据：带宽失衡

主界面 1280×800（`tauri.conf.json:17-18`），presence 页布局（`App.vue:586-596`）：

```css
.presence-layout {
  display: grid;
  grid-template-columns: var(--presence-vrm-w) minmax(0, 1fr);  /* 42% / 58% */
}
```

| 通道 | 面积 | 交互 | 承载内容 |
|------|------|------|----------|
| **对话** | ≈ 740 × 700px（58% 宽 × 满高） | 可滚动、可输入、可发送、可打断、可上翻 | 消息气泡流 + 输入框 + 发送 + 重说/别说了 |
| **生命** | ≈ 200 × 90px（`App.vue:648` `max-width: min(12.5rem, 52%)`） | `pointer-events: none`，不可点、不可读更多 | 状态一行 + 动向一行 + 时间痕迹一行（0.88 / 0.76 / 0.72rem） |

生命证据的三行小字，是 `presence-life` 浮层（`App.vue:220-234`），位置在形象区右侧 `top: 18%`，半透明底。**它是形象的注释，不是界面的主体。**

## 二、六个具体问题（按优先级）

### P0-1 视觉权重倒置

见 §一。后果：打开应用的第一眼认知是「一个聊天窗口」，生命证据降级为装饰性小字。
**改法见 §三·第一层。**

### P0-2 时间痕迹是静态快照，自己却是静止的

`requestTimeTraces()` 的**全部**调用点（`useQi.ts`）：

| 行 | 触发时机 |
|---|---|
| 821 | 连接建立时 |
| 838 | 切回存在页时 |
| — | 后端仅在 `server.py:1056`（清空记忆后）主动推一次 |

而它输出的文案（`time_traces.py:61`）是：

> 她记得 137 件事，其中 23 件正在慢慢淡去。认识第 96 天。

**一句声称「正在淡去」的文案，自己却只在连接和切页时刷新一次。**

这是当前最有杀伤力的自相矛盾——记忆褪色是本项目最独特的资产（赛道最大痛点是记忆断层，而栖甚至会「忘」），但它在界面上被做成了一张**照片**，不是一个**过程**。

对照：动向流 `activity_glance` 有新事件推送（`brain_delivery.py:177`），所以动向是活的、痕迹是死的。两者并排显示时，静止会更刺眼。

**改法见 §三·第二层。**

### P0-3 心跳完全不可见

- 后端：`rhythm.py:14-19` `HEARTBEAT_INTERVALS` = AWAKE 3s / AMBIENT 30s / SOLITARY 300s / DREAMING 1800s。
- 前端：唯一的时间感是 `presenceStatus`（`time_traces.py:64-82`）派生的**离散标签**——在这儿 / 在想 / 正在回你 / 自己待着 / 在做梦 / 睡着了。
- WS 的 30s `ping`（`server.py` `_ping_loop`）仅用于连接保活，**未显化**。

后果：3 秒一次的心跳——她最基本的生命体征——在界面上完全不存在。没有呼吸、没有微动、没有节拍。

灵魂书说「安静不是『没在运行』，是『在，但不打扰』」，但**当前界面上，安静看起来就是没在运行**。这是「像聊天机器人」最直接的来源：聊天机器人在没人说话时确实是死的，而栖不是——可用户看不出来。

> 此条与 9.1-#6「心跳不可见」为同一条，2026-08-29 已诊断，**至今未做**。

**改法见 §三·第三层。**

### P0-4 主动行为被降级成聊天消息

- `proactive.py`：`PROACTIVE_DAILY_LIMIT` 日限 3、冷却 check_in 4h / reach_out 8h。
- 产物经 `push_proactive_text` → `speech` → **落进 `TalkView` 气泡**。

后果（审计简报 §六 已点破）：**用聊天机器人的形态表达「我不是聊天机器人」，自相抵消。**

更糟的是：主动开口与被动回复在视觉上**完全无法区分**——同样的气泡、同样的位置、同样的配对结构。用户感知不到「这是她主动来找我的」，于是主动性这项资产也白费了。

**改法见 §三·第四层。**

### P1-5 数据模型的一问一答耦合（结构性）

| 耦合点 | 证据 | 后果 |
|--------|------|------|
| 消息表即对话转录 | `database.py:45-54` `messages(role TEXT)`，role 仅 user / assistant | 「她主动做的事」与「她回你的话」在数据层不分家 |
| Prompt 恒定单问结构 | `prompt_builder.py:180` 末尾恒置 `{"role":"user","content":user_message}` | LLM 上下文只能表达「一问一答」 |
| 回应恒置顶 | `gws.py:59-79` `arbitrate`，respond 族 rank 50 恒最高 | 「回应你」在架构层被定义为她的主导行为 |
| **清醒由用户消息驱动** | `rhythm.py:28-58` `determine_mode` 仅在 `interacting` 或静默 <5s 时 AWAKE | 你不说话，她在架构层就被降格为 idle |

最后一条最根本：**她的存在状态被用户消息驱动**，这是一问一答范式在架构最深处的残留。

**改法见 §三·第六层。**

### P1-6 具身层缺真正的状态机

- `avatar/states.py` 定义了 5 posture / 7 expression / 5 effect，但**前端不运行 FSM**，仅做表情映射（`AvatarController.map_state` 后端驱动）。
- `talking` 复用 idle 动画，无 speaking 专属动画。
- **`lockMouth()` 每帧把 aa/ih/ou/ee/oh 全部压 0**（`usePetVrm.ts:477-483`）→ 说话时嘴不动。

后果：VRM 是「静态立绘 + 表情切换」，不是「住在那里的人」。口型锁死是生命感硬伤。

> 此条 = 9.1-#1，2026-08-29 已诊断，**至今未做**。注意：文字流式 / 口型 / TTS 分片三者应**同包设计**，拆开做会互相返工（9.3 已注记）。

## 三、优化方案：六个层次

> **主轴**：把交互重心从「对话」迁移到「共处」——**对话降为共处界面中的一个通道，而不是界面的主体。**

### 第一层 · 空间重构：聊天是抽屉，不是房间（**已否决 · 不做**）

> **2026-09-05 维护者否决**：现行左右分栏（形象 + 满高谈区）手感够好；不改为「对话抽屉」。本层仅留诊断与史料，**不开任务包、不改布局**。

**原目标（已废）**：打开应用的第一眼是她和她的场域，不是消息列表。

| 项 | 现状 | 曾提案（已废） |
|---|---|---|
| 主区（形象 + 生命） | 42% 宽 | ~~60–65% 宽~~ |
| 生命证据 | 形象右上角 200px 浮层，`pointer-events: none` | ~~形象脚下三行地志~~ |
| 对话 | 58% 宽 × 满高的常驻气泡流 | ~~默认收起为底部抽屉~~ |
| 氛围 | 被压在右侧气泡背景之下 | ~~成为主视觉~~ |

**判据**：不适用（本层不做）。

### 第二层 · 时间痕迹连续化：让褪色成为可目睹的事件（**已否决 · 不做**）

> **2026-09-06 维护者否决**：现行静态痕迹已够用；不另开褪色事件旁白。本层仅留诊断史料，**不开任务包、不改码**。

**原目标（已废）**：把「记忆会褪色」从数据库事实变成用户能亲眼目睹的过程。

**判据**：不适用（本层不做）。

### 第三层 · 心跳外显：呼吸（**已否决 · 代码已回退**）

> **2026-09-05 维护者收回**：整刀不做；曾合入实现已 `git restore` / 删除。本层仅留诊断史料。

**原目标（已废）**：让「安静 ≠ 空白」在界面上成立。

- ~~后端：每拍推 `pulse`~~
- ~~前端：呼吸 / 光晕 / 光尘~~

**判据**：不适用（本层不做）。

### 第四层 · 主动行为的专属通道：她走过来说话

**目标**：让「她主动找我」在视觉上一眼可辨。

- 主动开口**不再进 `TalkView` 气泡**，改为「信笺」形态：VRM 先做 `notice`（看向你），一句话以信笺样式浮现在主区，停留后沉入回顾。
- 与被动回复的区分：位置不同、样式不同、**没有配对的「你」的气泡**（因为不是你问的）。

**判据**：她主动说的话，用户一眼能分辨「这是她来找我的」，而不是「我说了句什么她回了」。

### 第五层 · 口型与 idle 状态机（具身硬伤）

- 解 `lockMouth()`，用流式出字的 chunk 节奏驱动口型张合。
- 补 idle 呼吸 / 视线漂移 / thinking 微表情。
- **须与文字流式、TTS 分片同包设计**（9.3 注记：拆开做会互相返工）。

**判据**：她说话时嘴在动；她不说话时有呼吸和视线。

### 第六层 · 数据模型去对话化（结构性，最后做）

- `messages` 表扩 `channel`（`user` / `qi_reply` / `qi_proactive` / `system_trace`），或引入独立 `life_events` 表——让「她主动做的事」与「她回你的话」在**数据层**分家，而非只在 UI 层分家。
- `gws.arbitrate` 不再恒置顶 respond：用户不说话时，「她正在做的事」应与「回应你」有同等或更高权重。
- `determine_mode` 的 AWAKE 判定不应只由用户消息驱动。

**这层改动大、回归面广，建议前五层做完且感受验收通过后再评估。**

**判据**：C3 无人测试——72h 无人干预，界面仍能呈现连贯故事。

## 五、红线（继承既有契约，不可碰）

1. **可见化 ≠ 表演层**——界面每个状态必须对应后端真实发生过的事件；为「显得活着」而造的动画即违规（架构方案「真骨骼 vs 表演层」）。
2. **不报情绪数值、不做仪表盘、不做数字墙**（contract 硬规则）。
3. 朱砂红不大面积使用；界面默认安静，不用弹窗/红点/badge 制造打扰。
4. 不动反编造硬闸、不动 assist 诚实、不动 irreversible 确认门。
5. 不动 look / open / write 白名单与权限体系（`qi/action/permission.py` 阶段门控）。
6. **禁靠表达层堆情绪词 / 加人设 prompt 解决体验问题**——这是本方案与"让 prompt 更像人"路线的根本区别。本方案全部改动在**通道与形态**，不在话术。
7. 新机制判据：改变她的处境，不是只改维护者对她的印象。
