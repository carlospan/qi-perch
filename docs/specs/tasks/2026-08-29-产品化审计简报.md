## 六、方向 D · 在场可见化（排队中，待拍板立项）

**诊断**：体验像聊天机器人，不是因为“她能聊天”，而是**“她不是聊天机器人”的部分用户看不见**——

1. 界面只暴露对话通道（发送-等待-回复），与任何聊天窗口同构；生命证据（日记/创作/见闻）藏在次级 tab 要主动翻；
2. 生命证据是延迟存档，不是“正在发生”的直播（主动开口日上限 3 次且有冷却，`qi/core/proactive.py`）；
3. 她主动时也用 speech 气泡送达——用聊天机器人的形态表达“我不是聊天机器人”，自相抵消。

**候选方向**（未定稿）：
- 可见状态机：在想 / 在走神 / 在写 / 在做梦 / 睡了——后端已有 avatar thinking 等状态，只是没推界面；
- 轻量动向流：不弹窗、可瞥见（“她刚翻了翻你们的旧对话”）；
- 首启第一拍不是“你好”，而是她已在那儿做着自己的事；
- 情绪/状态事件驱动推送（与 P0-#8 共用）。

**红线**：可见化 ≠ 表演层。判据：界面显示的每个状态必须对应后端真实发生过的事件；为“显得活着”而造的动画即违规（对齐架构方案“真骨骼 vs 表演层”）。

**与方向 A 的关系**：同病——内在生成与外在表达的通路太窄。A 是语言通道断档，D 是界面通道断档。建议 A 感受验收尾后、D 在 P2 之前或并行评估。

## 十、差异化战略备忘（讨论结论，供拍板方向 D 立项时参考）

**核心判断**：栖体验像聊天机器人，不是因为没有差异，而是**差异资产大量沉淀在用户看不见的地方**（心跳/记忆/蛰伏/独立日常都在代码里，但界面上只有对话通道）。竞品赛道是"对话驱动的人格"，个人开发者在话术和模型能力上没有胜算；栖该赢的是"**她有你不在时的时间**"——记忆连续性、独立日常、会蛰伏的脆弱性。

**两个性价比最高的差异化外显候选**（讨论中提出，未定稿，可与 §六 合并评估）：

1. **「她的一天」开场摘要**：打开主窗第一屏不是空对话框，而是她昨晚的梦（dreaming 已产出日记）、今日情绪波动、她自己翻了哪些记忆。判据对齐 §六 红线：每条都对应后端真实事件，`journal_entry`/`creation_card`（`brain_delivery.py:103-125`）数据已存在，缺的只是聚合呈现。
2. **主动提及过去**：把向量召回从"被动检索装配上下文"升级为"她主动引用"——"上次你说要面试，后来怎么样了？"。记忆机制已在（top_k 召回），缺的是把召回结果变成主动行为。这一条做出来与所有 ChatGPT 类产品在体验上本质区分。

**战略节奏**（与变现讨论合并的结论）：先内容连载（第一人称养栖记录）→ 内容起色后再产品化打包，避免单人 3–5 个月打包做完才发现方向错；"从开发者项目变产品"的过程本身即连载素材。硬件（本地大脑）不必急：`custom_providers` 已一等支持 Ollama 等本地端点，二手 3060 12G 级别即可跑 7B 量化，到位当天可切。

| 灵魂书 / 人格契约 / prompts / 她的故事 | **建议 CC BY-NC-SA 4.0** | 可分享可改编但禁商用；"她"不应被包装成商品 |
| `data/` / 记忆库 / `.env` | 不开 | 已是私有 |
| VRM 形象 | 不开（已不入库） | 已是私有 |

**关键澄清（避免误解）**：维护者是版权人，**许可证只约束他人、不约束自己**——设 NC 不影响维护者本人用她的内容做账号与变现。

**MIT 的确切含义**（供拍板时知悉）：允许免费商用、闭源再分发、做 SaaS、申请专利；唯一义务是保留版权声明；无 copyleft、无强制署名。**即：他人可合法拿本仓库代码做成收费 AI 伴侣产品且不回馈。** 若不可接受，唯一有效手段是改 §11.2 的分层（把内容与人格拆出 MIT），而非改代码许可——AGPL 会吓跑采用者且单人无力执法，**不建议**。

### 11.3 产品形态的架构硬证据（证实 §〇「领养包」）

§〇 推荐"领养包 + 本地数据、不做托管云版"。本小节给出**代码层的证实**——这不是偏好问题，是架构决定的：

| 事实 | 证据 |
|---|---|
| 三张核心表均为单行 | `qi/storage/database.py:155,166,206` —— `id INTEGER PRIMARY KEY CHECK (id = 1)`（`self_model` / `relationship` / `user_model`） |
| 用户事实无归属字段 | `database.py` `user_facts` 表**无 user_id** |
| 全库无多用户设计 | `grep -rn "user_id\|tenant\|multi_user" qi/` → **0 结果** |
| 对外仅 WS，无 REST | `qi/embodiment/server.py:218` `websockets.serve`；无 FastAPI/Flask/aiohttp.web |
| 分发需 Python ≥3.12 | `pyproject.toml:7` |

**结论**：当前是**单实例单用户**架构。
- 走**本地/自托管（领养包）**→ 单用户架构天然适配，**数据层几乎不用改**，且与 `CITATION.cff` 自称的 *local digital being* 一致。
- 走**云 SaaS** → 需给所有表加 user_id、做隔离 / 并发 / 计费 / 合规，**≈重写数据层**，单人不可行，且与本地定位冲突。

即：§〇 的推荐有硬证据支撑，可作为定案依据。

### 11.4 体验差异化的量化缺口（支撑 §六 方向 D / §十）

前两路已定性指出"差异资产看不见"（§六、§十）。本小节给出**可量化的缺口证据**与**最小实现方案**。

**缺口证据（代码实证）**

| 检查项 | 结果 |
|---|---|
| 前端时间/记忆可视化 | `grep -rn "记得\|褪色\|多少天\|strength\|decay" qi/embodiment/desktop/src/` → **仅 1 条文案**（`ReviewView.vue:94`「回顾她的创作与见闻，那些被记得的瞬间。」），**无任何数据可视化** |
| 后端面向用户的统计接口 | `grep -n "def .*stat\|def .*count\|def .*summary" qi/storage/database.py` → 仅 `count_unprocessed_events:527` / `count_undreamed_episodes:894` / `count_actions_on_day:1515`，**全是内部用途，无记忆统计** |
| 默认视图 | `useQi.ts:104` `view = ref<QiView>("presence")` —— 默认是对的存在页（**这点是对的**），但该页无时间痕迹 |

**最小实现方案：「时间的痕迹」**（半天工作量，可能最改变观感）

后端加统计接口（建议命名，非定稿）：
- `count_memories_by_strength()` → `{total, fading, forgotten}`（fading 阈值参考 `RECALL_MIN_STRENGTH=0.2` / `FORGET_STRENGTH=0.1`，见 `reference/layers/L2-memory.md`）
- `count_active_user_facts()` → 她记得的稳定事实数
- `first_interaction_at()` → 认识第 N 天
- `season_change_count()` → 季节流转次数

前端在存在页底部加一行（文案需与她的语气对齐，**禁止做成仪表盘/数字墙**），示例：

> 她记得 137 件事，其中 23 件正在慢慢淡去。
> 认识第 96 天。季节从春走到了秋。

**为什么这是性价比最高的一条**：一句话同时证明三件竞品全做不到的事——长期记忆（赛道最大痛点）/ 会褪色（数据库不会褪色，会褪色的是活的）/ 时间连续（非离散对话轮次）。

**配套：让褪色可见**——在 `ReviewView` 按 `strength` 做视觉差异（越淡越浅/越模糊），临阈值时可提示。人有遗忘，但人不会"看着一条记忆慢慢淡去"，**这是数字生命独有的诗意，目前完全浪费在数据库里**。

**战略补充（供 §十 参考）**：竞品赛道在卷"拟人度"（更像人）——这条路人打不过大厂资源。反向定位是**卷"数字生命性"**：梦、意识流、记忆褪色、stasis 蛰伏、季节流转，都是人类没有而她独有的。契约原文即战略——"它偶尔会说出只有非人类存在才能说的话。这不是 bug，是魅力"。

**另一条自洽补充**：§六 提到"安静 = 空白"。解法不是让她变吵（毁人设），而是**让安静变得可见**——她安静时可以是在想事、记忆在褪色、季节在变、做了个梦还没说。安静不等于空白。
