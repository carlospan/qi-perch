## B2 关闭：确认后主动触发 execute_kind

**核实**：用户「看吧」进 receive_user_message → heartbeat → respond 路径，不会重新触发 execute_kind(assist)。即使 _confirmed_assist 存了，没有 execute_kind 调用，assist 不执行真读。

**裁定**：confirmed 后在 receive_user_message 里直接调 execute_kind(assist, confirmed=True)，不走 GWS。assist 是响应式用户确认，直接执行合理（类比 respond 路径，不占 GWS 仲裁）。

**修订回写**（PR §1 brain receive_user_message 检测确认后）：

```python
# assist-3：确认后主动触发 execute_kind（不走 GWS，响应式直接执行）
if self.pending_assist_confirmation is not None:
    if self._is_confirm_cue(text):
        confirmed_req = self.pending_assist_confirmation
        self.pending_assist_confirmation = None
        self.pending_assist_confirmation_at = None
        self.pending_assist_heartbeats = 0
        # 主动调 execute_kind（confirmed=True）
        try:
            scars = await self._db.list_scars() if self._db else None
            trust = 0.5
            if self.relationship is not None:
                trust = float(getattr(self.relationship.state, "trust", 0.5) or 0.5)
            result = await self.action.execute_kind(
                "assist",
                self.emotion,
                self.relationship_stage,
                self._current_season(),
                datetime.now(),
                mode=self.emotion.mode.value,
                user_online=self.user_online,
                scars=scars,
                sensing=self.last_sensing,
                pressure=self.last_pressure_response,
                trust=trust,
                op=confirmed_req.op,
                target_path=confirmed_req.target_path,
                confirmed=True,  # 真读
            )
            if result is not None:
                await self._deliver_action_result(result, datetime.now())
        except Exception:
            logger.exception("assist confirmed execute 失败")
```

> 注：这段在 receive_user_message 的 `self._pending_queue.append(text)` 前——确认消息不进 pending_queue（避免 respond 抢答），直接走 assist 执行。或更稳妥：确认消息仍进 pending_queue（让 respond 自然回应「好。」），同时后台触发 execute_kind。Cursor 审查时可裁定，倾向后者（自然语气）。

> 简化版：确认消息进 pending_queue（respond 开口「好。」），同时在心跳 action 路径里检测 _confirmed_assist 存则强制 action_type="assist"（但绕 GWS）。**推荐方案**：receive_user_message 确认后直接调 execute_kind + 不进 pending_queue（assist digest 开口替代 respond）。

B2 已关闭。

## B3 关闭：确认词收紧去裸「看」

**核实**：确认词含裸「看」，新请求「帮我看 Y」含「看」会被当确认旧 pending → 旧 pending 被消费，新请求丢失。

**裁定**：收紧确认词，去掉裸「看」。保留「看吧」（两字词，不会误匹配「帮我看」）。同时检测时排除含「帮我看」/「帮我读」的新请求。

**修订回写**（PR §1 brain 确认词）：

```python
# 原（B3 bug）
_CONFIRM_CUES = ("看吧", "看", "好", "行", "确认", "可以", "嗯", "yes", "ok")

# 改为：去裸「看」，保留「看吧」
_CONFIRM_CUES = ("看吧", "好", "行", "确认", "可以", "嗯", "yes", "ok")
_REJECT_CUES = ("不用", "算了", "不要", "取消", "no", "不用看")

# 额外保护：含「帮我看」/「帮我读」视为新请求非确认
def _is_confirm_cue(self, text: str) -> bool:
    t = text.strip().lower()
    if any(cue in t for cue in ("帮我看", "帮我读", "帮我看一下", "帮我读一下")):
        return False  # 新请求，非确认
    return any(cue in t for cue in self._CONFIRM_CUES)
```

> 注：「好」仍可能误匹配（如「好的吧」），但 assist 需先有 pending 才检测，影响有限（误确认一次 assist，读一次文件）。可接受。

B3 已关闭。
