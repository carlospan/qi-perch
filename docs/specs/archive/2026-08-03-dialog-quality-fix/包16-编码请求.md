# 包 16：对话质量修复——编码请求（交 Cursor 执行）

> 类型：缺陷修复（对话质量）｜纪律：仿包 15，仅新增/加固，不删既有防护

## 目标

修三个经 OpenCode 提报、Cursor 复核、CodeBuddy 活库核实三方对齐确凿的代码缺陷：
1. 对话生成路径无跨轮去重 → 整段回答被原样复读（id 984 == id 1004）。
2. `FactNoticer` 人名/地点门控漏网 → active 脏事实（id 18「他希望被叫做过去拿」、id 14「他在写谁的代码」）污染 prompt。
3. 表达层不吸收用户「直接一点/简短」反馈 → 栖持续 200+ 字长文。

## 改动一：对话回复跨轮去重

落点：`qi/core/expression.py` 表达链路（或 brain 落库前，由 Cursor 选定最小侵入点）。

- 新增纯函数 `recent_qi_replies(db, limit=5) -> list[str]`：
  复用 `db.load_recent_messages(limit=limit+用户条数)`，过滤 `role=="qi"`，返回最近 N 条栖回复文本（旧→新）。
- 复用 `qi/inner_life/consciousness.py:178` 的 `char_jaccard`（import 即可，不改它）。
- 在新回复 `text` 落库/返回前：
  - 与 `recent_qi_replies` 每条算 `char_jaccard(text, hist)`；
  - 任一 `> 0.85` → 标记重复，触发轻量重生成（追加系统约束「不要重复刚才说过的话，换个说法回应」）；
  - 重生成仍 `> 0.85` → 降级为模板短回应（`render_template` 的 acknowledge/share_state 简版），不空转不沉默。
- 阈值/窗口定义为模块常量：`REPLY_DEDUP_THRESHOLD = 0.85`、`REPLY_DEDUP_WINDOW = 5`。

### 2.2 `_purge_bogus_identity`（line 669 起）
