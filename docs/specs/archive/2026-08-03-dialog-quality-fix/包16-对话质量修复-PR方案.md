# 包 16：对话质量修复（回复去重 + 事实门控 + 表达简短）

> 类型：缺陷修复（对话质量）｜依赖：包 15 已 ✅（阶段四退出后观察期）
> 关联：OpenCode 系统层审查 + Cursor 复核 + CodeBuddy 活库核实三方对齐
> 纪律：仿包 15——先方案、Cursor 编码、04 验收 Agent 独立验收

## 0. 一句话

深度对话暴露三个真实缺陷：①对话生成路径无跨轮去重，导致整段回答被原样复读（id 984=id 1004）；
② `FactNoticer` 的人名门控有已知漏洞，「他希望被叫做过去拿」「他在写谁的代码」等误判 active 事实污染 prompt；
③表达层不吸收用户「直接一点/简短」反馈，栖持续 200+ 字长文。本包三处一起修。

## 1. 三方核实结论（活库实测为据）

| # | 问题 | 现象 | 真实范围/机制（纠偏后） |
|---|------|------|------|
| 1 | 回复逐字重复 | ✅ id 984(19:50:13) 与 id 1004(20:13:28) 整段相同 | 对话生成路径无跨轮去重；`char_jaccard` 仅意识流（consciousness.py:178），不覆盖回复。非"检索/重试返回旧生成"（无代码证） |
| 2 | user_facts 脏数据 | ✅ 有 | **active 污染仅 id 18（他希望被叫做过去拿）+ id 14（他在写谁的代码）**；真名 id 1 早被 id 18 取代（superseded_by=18），不在 active 集。原"5条全进prompt"夸大，已纠 |
| 3 | 表达未吸收简短 | ✅ 用户均 11字 / 栖均 209字；#989「你可以直接一点吗」后 #990 仍 300字 | `card.length=="short"` 仅控模板降级，无"用户要求简短→强制 short"的机制 |

> 备注：OpenCode 原提 #3(security 无疤)/#4(意识流停更)/#6(raw_events) 经核实为"记忆缺口/设计待查/管线脱节"，**不属本包代码范围**（#3 是设计权衡、#4/#6 需单独诊断），本包只收三条确凿可修的代码缺陷。

## 2. 根因

### 2.1 回复去重缺失
- `qi/inner_life/consciousness.py:178` 的 `char_jaccard` 去重只用于意识流 `meta` 生成（line 194）。
- 对话回复路径（`qi/core/expression.py` / brain 表达链路）不保留"最近 N 条栖回复"做相似度比对，LLM 偶发复读历史答句时无拦截。

### 2.2 事实门控漏网
- `qi/memory/facts.py:267` `looks_like_person_name` 已含「程序有问题」「那今天几月几号」黑名单（注释自证已知），但：
  - `identity_name_fragment` 对「他希望被叫做过去拿」解析出"过去拿"——`looks_like_person_name("过去拿")` 因不含黑名单动词会误判为真名；
  - `_purge_bogus_identity`（line 669）对 `content.startswith("他希望被叫做")` 显式 `pass` 跳过清理（line 696-697），导致 id 18 漏网；
  - id 14「他在写谁的代码」是 `location` 类型（state），门控只拦 identity，location/state 的"谁的代码"类短语未拦。

### 2.3 表达不吸收反馈
- `qi/core/expression.py:25` 仅 `card.length=="short"` 决定模板简版，但 `length` 来自意图卡，用户口语「直接一点/简短点」未被映射到 `short`。

## 3. 修复方案（最小、仿包 15 纪律）

### 3.1 对话回复跨轮去重（新增，不碰意识流既有逻辑）
- 在 brain 表达链路落库前，取最近 N 条栖回复（新增函数 `recent_qi_replies(limit=5)`，复用 `db.load_recent_messages` 过滤 role=="qi"）；
- 对新生成回复 `text` 与每条历史做 `char_jaccard(text, hist) > 0.85` 判定，命中则：
  - 触发一次轻量重生成（追加约束"不要重复刚才说过的话，换个说法"）；
  - 若重生成仍超阈值，则降级为模板短回应（不空转、不沉默）。
- 去重阈值/窗口常量集中定义，便于调参。

### 3.2 事实门控加固（修 facts.py，不删既有逻辑）
- `looks_like_person_name`（line 267）：扩充黑名单动词，覆盖"过去拿/谁的代码"类——增 `"拿","代码","写","希望被叫做"` 到拒识集合（line 290-297 段）；
- `_purge_bogus_identity`（line 696-697）：移除对 `他希望被叫做` 的 `pass` 跳过，改为一律走 `looks_like_person_name` 校验，校验失败即 `retire()`；
- 新增 `location`/`state` 类型的短语门控：对含「谁的代码/在写什么」等无实指 location 的抽取，标记为非稳定或拒入 active（复用 `is_question_or_hypothetical` 思路，扩到 location 类）。

### 3.3 表达吸收简短反馈（expression.py + intention 映射）
- `qi/core/intention.py` 意图识别：新增用户对"直接一点/简短/别绕/长话短说"的识别 → 设 `card.length = "short"`；
- `expression.py`：`length=="short"` 时除模板降级外，若走 LLM 措辞，prompt 注入"用 1-2 句、克制长度"硬约束（不超 60 字）。

### 3.4 防回归测试
- `tests/test_expression.py`：构造历史回复 + 复读文本，断言去重触发重生成/降级；
- `tests/test_facts.py`：断言 `looks_like_person_name("过去拿")==False`、id 18 类经 `_purge_bogus_identity` 后非 active；
- `tests/test_intention.py`：断言"直接一点"→ `length=="short"`；
- 既有测试不变。

### 3.5 一次性数据修复（清存量 active 脏事实）
- 新增 `tools/repair_user_facts.py`（仿 `repair_consciousness_stream.py`）：预演列出 + `--apply` 删除/retire id 18、id 14（及任何 `looks_like_person_name` 失败却 active 的 identity）。

## 4. 验收标准

1. 回复去重：构造 id 984-style 复读，断言表达链路拦截并产出不同文本（单测）。
2. 事实门控：`looks_like_person_name("过去拿")==False`；`_purge_bogus_identity` 后 id 18 非 active；id 14 类 location 误判不入 active。
3. 表达：用户说"直接一点"→ `card.length=="short"` 且 LLM prompt 含短约束。
4. 全量 `pytest` 通过（含新增），`ruff` 零问题。
5. 数据修复脚本预演命中 id 18/id 14，`--apply` 后 active 污染清零。

## 5. 红线（库内禁止）

- 不删 `looks_like_person_name` 既有黑名单（只扩充，不删已知项）。
- 回复去重只读历史回复，不写库（除正常落库新回复）。
- 表达 `short` 约束不破坏 contract 人格红线。
- 不引入新依赖。
