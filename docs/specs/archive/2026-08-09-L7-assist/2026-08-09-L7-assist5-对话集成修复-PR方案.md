### 3. `qi/core/brain.py` 确认兜底 + 粘性目标（HITL3=a，修订吸收 B1/B2/B3）

**问题**（Cursor 交叉审查）：
- B1：`last_user_message` 每次用户消息都覆盖（L1247）——真·1522 场景中间「啊？你看到了什么」覆盖路径，补执行 parse 不到。须粘性 `last_assist_target`
- B2：`_CONFIRM_CUES` 含裸「好」「行」「嗯」（L1118）——pending=None 时全量短路会劫持闲聊「好呀」「嗯嗯」。须绑近期 assist 上下文 + 收窄确认词
- B3：引导句只 return、不 `_deliver_qi_message`——桌面 WS 可能无开口

**改为**：

**3a. 粘性 `last_assist_target`（修 B1）**：

- `__init__`（L123 附近）加：
```python
self.last_assist_target: str | None = None   # 粘性：最近一次 assist 请求的目标路径（assist-5）
self.last_assist_target_at: datetime | None = None
```
- L1256 解析到 assist_req 时设：
```python
self.last_assist_target = assist_req.target_path
self.last_assist_target_at = datetime.now()
```
- 拒绝（L1223-1227）/ 超时清理处：一并清 target；新 assist 请求覆盖
- **pending 确认成功（L1228-1239）后 target 保留**（粘性窗口内可补执行）
- 超时窗口复用 pending 的 5 分钟或 3 轮心跳逻辑（同 HITL2 先到先清）

**3b. 收窄确认词 + 绑上下文（修 B2）**：

- 新增常量（L1118 附近）：
```python
# assist-5：pending 已消费后补执行的确认词（短语级，不含裸「好/行/嗯/可以/yes/ok」）
_CONFIRM_CUES_REEXEC = ("看吧", "你读吧", "好你读吧", "读吧", "确认", "ok 看吧", "行 看吧")
```
- 兜底分支**不用** `_is_confirm_cue`（全量含裸词），改绑 `self.last_assist_target is not None` + `_CONFIRM_CUES_REEXEC` 短语匹配

**3c. 兜底分支（修 B3，放在 L1244 `_clear_pending_assist` 之后、assist-4 解析分支之前）**：

> **复审-1 修订**：引导句**必须在「命中 reexec 窄词」分支内**——补执行落空 / 无新鲜 target 时才 deliver 引导句；非 reexec 消息绝不短路，直接落入 assist-4 解析 / 正常对话。

```python
# assist-5：pending 已消费但用户仍短语确认（1522 场景）——粘性目标补执行
if self.last_assist_target is not None and self._is_confirm_reexec_cue(text):
    now = datetime.now()
    if self._assist_target_fresh(now):
        target = self.last_assist_target
        self.last_assist_target = None  # 补执行后清（防重复）
        result = await self._execute_assist_on_request(
            AssistRequest(op="read_file", target_path=target),
            confirmed_override=True,
        )
        if result is not None:
            await self._deliver_action_result(result, datetime.now())
            return (result.get("qi_line") or "").strip() or None
    # 命中 reexec 窄词但 target 不新鲜 / 补执行落空 → 引导句 deliver（修 B3）
    await self._deliver_qi_message("嗯？你想让我看什么？", datetime.now(), proactive=False)
    return "嗯？你想让我看什么？"
# 非 reexec：绝不短路，落入下方 assist-4 解析 / 正常对话
```

- 新增辅助方法：
```python
def _is_confirm_reexec_cue(self, text: str) -> bool:
    t = text.strip().lower()
    return any(cue in t for cue in self._CONFIRM_CUES_REEXEC)

def _assist_target_fresh(self, now: datetime) -> bool:
    if self.last_assist_target_at is None:
        return False
    return now - self.last_assist_target_at <= timedelta(minutes=5)
```
- `_execute_assist_on_request`（L1141）加 `confirmed_override: bool = False`，透传 `confirmed=confirmed_override`（assist-4 既有调用 L1261 不传，默认 False，行为不变）

> 注意：确认成功分支（L1228）后 target 保留，故 1522 场景「看吧/好你读吧」会命中 3c 补执行；前端按钮路径（已消费 pending）后用户再短语确认同样补执行，无副作用（只读）。
