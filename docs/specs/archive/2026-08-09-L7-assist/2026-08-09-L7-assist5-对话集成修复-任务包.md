## 背景（数据实证）

用户让栖读 `D:\ai\栖.txt`（文件存在，内容「我爱栖」），对话出现：

| msg | 内容 | 真相 |
|---|---|---|
| 1514/1516 | 用户「读一下」→ 栖 respond **编造**「我读不到，你的文件系统隔着距离」 | LLM 不知道 assist 能力 |
| 1518 | 栖「要我看 栖.txt 的话，说一声我就看。」 | confirm_gate 生效（assist-4）|
| 1519 | 栖「我看到了一颗温柔的心」 | 用户点前端「看吧」→ 真读「我爱栖」→ digest 转译跑偏 |
| 1521 | 栖 respond 又编造「我没有真正看到内容」 | LLM 不知道刚读过 |
| 1522 | 用户口头「好你读吧」 | confirm cue 命中 |
| 1523 | 栖 respond 再编造「我读不到它」 | **pending 已被 1519 消费 → confirm 走空 → 落入 LLM 编造** |

**证据**：assist actions 表 = 0 条（`assist.execute` 不 `insert_action`，Step 5 违约）。

**根因三层**：
1. `assist.execute` 不写 actions 表 → assist 无留痕，`recent_actions` 不注入 → **respond LLM 不知道栖刚读过文件**（1521/1523 编造来源）
2. conversation prompt 无 assist 语义 → 用户请求读文件时 LLM 编造「读不到你的文件系统」（1514/1516）
3. 口头确认空转：pending 被前端按钮消费后，用户再口头确认 → confirm cue 命中但 pending=None → 落入 respond LLM 编造（1522/1523）

## 目标一句话

修 assist 对话集成三层：assist 留痕 + prompt 语义 + 口头确认兜底，让「帮我读文件 → 确认 → 真读 → 不编造」在真实对话闭环。

## 范围边界（不做清单）

- 不改 assist-1/2/3/4 既有结构（execute_kind / confirm_gate / pending 超时不动）
- 不改前端（AssistConfirmCard 不动；前端按钮路径已通）
- 不做 irreversible / assist 写操作
- 不重写 digest 转译自由度（N4 观察项，非本包）

## HITL 拍板（待拍）

1. **assist 留痕范围**——倾向 a：
   - a. 成功（真读）+ failed_capability（关系不够/文件不存在/不支持）都 insert_action；confirm_gate（confirm_required）不 insert（未执行）
   - b. 仅成功 insert
   - 理由：失败也留痕才符合 explore 先例（`failed_capability` 也写 actions）；confirm_gate 是「请求确认」不是行动完成
2. **conversation.txt 语义注入**——倾向 a：
   - a. 静态加一条硬规则：「用户请求看文件/读文件时，你有读文件的协助能力；真读过就按记忆说，没读过或找不到就老实说『没找到』——不要编造『读不到你的文件系统』『隔着玻璃』」
   - b. 动态注入（pending/请求存在时才注入）
   - 理由：静态更稳，防止任何路径下 LLM 编造；动态注入在 assist-4 对话拍短路下基本用不到（短路时不走 respond LLM）
3. **口头确认兜底**——倾向 a：
   - a. 粘性 `last_assist_target`（修 B1：last_user_message 被中间句覆盖）：assist 请求解析时存目标路径，pending 确认后保留，超时/新请求覆盖；pending 已消费后用户短语确认（「好你读吧」等，修 B2 收窄词表不含裸「好/行/嗯」）→ 粘性目标补执行（confirmed=True）；parse 不到目标 → 引导句走 `_deliver_qi_message`（修 B3）
   - b. 只回引导句（不补执行）——否（1522 场景用户确已表达「看」）

## Spec（外部可观测行为）

1. 用户「帮我看 D:/x.txt」→ assist confirm_gate 开口（assist-4 已有，此刻 actions 表**尚无** assist 记录）；真读成功或失败后，actions 表才出现 assist 记录
2. 用户点「看吧」或口头「好你读吧」→ 真读 + digest 开口 + actions 表出现 assist 成功记录
3. 用户重复「好你读吧」（pending 已消费）→ **仍补执行真读**，不再落入 LLM 编造「读不到」
4. 文件不存在/关系不够 → assist `_fail` + actions 表出现 failed_capability 记录 + 开口诚实
5. 任何路径下栖不再说「我读不到你的文件系统 / 隔着玻璃」

## 验收

- actions 表有 assist 记录（成功 + 失败）
- 1522 场景（重复确认）补执行真读
- conversation prompt 含 assist 语义（人工可查）
- 全量 ≥567 passed
