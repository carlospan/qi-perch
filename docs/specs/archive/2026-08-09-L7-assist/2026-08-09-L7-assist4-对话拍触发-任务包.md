## 背景

assist-2/3 落地后，相处验证发现 assist **从未在对话拍真正执行**。

**架构洞**：`brain._heartbeat` L757 `elif pending is None:` 才进 GWS idle（含 `collect_contenders` + `action.tick`）。对话拍 `receive_user_message` 把用户消息 append 进 `pending_queue` → `pending is not None` → **跳过 GWS idle → assist 候选永远不生成 → execute_kind("assist") 永不执行**。

assist-2/3 的设计假设是「对话拍解析 → 心跳 GWS 仲裁 assist → execute_kind」，但对话拍主路径是 respond（pending），不进 GWS。设计假设和现码脱节。

## 目标一句话

修 assist 对话拍架构洞——`receive_user_message` 解析到 `last_assist_request` 时，**跳过 conversation LLM + 不进 pending_queue**，直接 `execute_kind("assist", confirmed=False)` → confirm_gate 开口「要我看的话，说一声我就看」**作为 respond** 返回用户；assist 是响应式不走 GWS（不与 share/tend/explore 仲裁）。

## 范围边界（不做清单）

- 不改 `_heartbeat` 主路径
- 不改 GWS / collect_contenders / trace
- 不改 assist.py / layer.py / volition.py
- 不改前端（AssistConfirmCard.vue 不动）
- 不做 irreversible
- 不做 assist 写操作（只读 confirmed=False → confirm_gate 开口）

## HITL 拍板（已追认 a/a/a）

1. **assist 开口 = respond**（跳过 conversation LLM）—— a
   - 理由：assist 响应式（contract 第 25 条），confirm_gate 开口就是对用户「帮我看 X」的 respond
   - 不违反「respond 永不被压过」——assist 开口就是 respond 本身
2. **不进 pending_queue**（不走 respond LLM 路径）—— a
   - 理由：assist 开口已替代 respond，不进 pending_queue 避免重复开口
3. **信任门控复用 assist.py 现有 `_confirm_gate`** —— a
   - stranger → failed_capability 开口「熟一点」（assist.py 现有逻辑）
   - friend+ → confirm_gate 开口「要我看的话，说一声我就看」
   - bonded → 同 friend+（assist-3 confirmed=False 路径）

## Spec（外部可观测行为）

1. 用户「帮我看一下 D:/x.txt」→ 栖**不走对话 LLM**，直接开口「要我看的话，说一声我就看」（friend+）/「熟一点」（stranger）；谈区出 AssistConfirmCard 确认卡
2. 用户「看吧」→ 栖真读文件 + digest 开口（assist-3 已接）
3. 用户「不用」→ 栖「好。」（assist-3 已接）
4. 无 assist 请求的普通消息 → 走原 respond 路径（不影响）
