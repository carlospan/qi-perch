## 必须整改（阻塞编码）

### B1. 病征覆盖不足——Spec 与实证错位

本场硬伤类型 vs 本包手段：

| 硬伤 | 类型 | 「新实体」闸能否拦 |
|------|------|-------------------|
| `#1326`「你问你要电脑做什么呢」 | 无出处共同回忆问句 | **基本不能**（无新人名/地名） |
| `#1358` 本地部署谁先说 +「胡说/说服力」对白 | 主体倒置 + 编造对白 | **不能**（实体「本地部署」可能已在近聊/材料里） |
| `#1350`「我说不会」实为「我会想试试」 | 极性/结论翻反 | **不能** |
| `#1356`「会问你能不能叫我栖」 | 施事倒置 | **不能** |
| `#1318` 旧哲学对话答欲望问 | 检索串台 / 答非所问 | **不能**（材料里实体是「真的」，只是答错题） |

**整改要求（择一写进 PR 方案，推荐组合 A+C）：**

- **A. 共同回忆声明闸（优先）**  
  检出「那天/那晚/凌晨/你问/你说过/我说了…」等**确定回忆句式**时：  
  - 卡内无 `memory`/`fact` 实材 → violation（扩展现有「伪记忆句式」，且**不依赖** must 里才有「不假装记得」）；  
  - 有实材 → 声明中的关键短语须能在 materials 原文（或显式 quote 字段）中找到子串/归一化命中，否则 violation。  
  用 `#1326/#1358` 类句子做回归测。

- **B. 检索相关门（建卡侧，可同包或标为包 N5-b）**  
  语义命中但与当轮 topic/intent 不对题 → 不进卡或 `low_confidence` + 禁止当确定回忆讲。对上 `#1318`。

- **C. 本包若坚持「只做实体闸」**  
  必须改 Spec/任务包标题与验收口径为「实体一致性加固（子集）」，并**显式声明不覆盖**上表硬伤；另开任务包跟共同回忆声明闸。禁止对外写成「通用事实一致性已落地」。

> 审查倾向：**不要选纯 C 糊弄**；至少把 A 做进本包，B 可拆包但要在主线写清依赖。

### B2. 「全量 violations」会误伤软检

现行 `assert_reply_respects_card` 文档写明：`无支撑自我认知结论` 为**软检 / 仅 trace**。  
PR 方案 2.2 改为「有 viols 就重生」，会把软检升级成硬闸，可能改变主动开口行为面。

**整改**：硬闸只消费明确列表，例如：

```text
HARD = 卡外专名 | 伪记忆句式 | 施教关系反转 | 空卡编造共同回忆 | 虚构实体 | （新增）共同回忆无出处
SOFT = 无支撑自我认知结论  # 仍不阻断
```

`expression` 只对 HARD 重生；SOFT 可打日志/`intention.evidence`。

### B3. 实体提取方案过粗，缺失败模式

`re.findall(r'[\u4e00-\u9fff]{2,4}')` + 过滤表：

- **误杀**：口语双字（「愿意」「珍惜」「紧张」）、关系词、用户名断片易进「新实体」。  
- **漏杀**：本场主病不靠专名。  
- **`_is_definite_fabrication` 未定义可测规则**：方案停留在散文，Cursor 无法稳定实现。

**整改**：在 PR 方案中写死：

1. 已知集 = materials 全文 n-gram ∪ 近聊窗口（若允许）∪ 固定白名单（意象/情绪/功能词表，落代码常量并单测）。  
2. 「虚构实体」**第一版只拦**：materials/近聊皆无、且命中「疑似专名」启发（如书名号、少见四字专名、显式「叫××的人」）——宁漏勿杀。  
3. 给 3 个**应拦** + 3 个**不应拦**的金样例（含「深水/石子/树叶」）。

### B4. `expression` 去重重生路径未改全

## 建议整改（不阻塞，但应写进方案）

### S1. 伪记忆闸与 must 解耦

现行伪记忆仅在 must 含「不假装记得」时触发；而「不假装记得」主要挂在 `answer` 空材。  
`free_talk` 有污染/弱材料时仍会编「你问过…」。  
共同回忆闸（B1-A）应**默认对话通道启用**，不以 must 文案为开关。

### S2. prompt「生动呈现」注意 R2 / 瘦身

诚实边界句 ✅。  
「以温暖第一人称把 memory 扩写进 system」⚠️：可能变相加厚 prompt、让模型把扩写当新事实。  
建议：materials **原文短引** + 一句诚实边界；「生动」放在用户可见回复侧，不要在 system 里二次小说化素材。

### S3. 回归用例必须钉 message id

验收栏增加（至少）：

- [ ] 合成回复含「你问『你要电脑做什么呢』」且 materials 无此句 → HARD violation  
- [ ] 合成回复含文学意象「深水/石子」→ 无虚构实体  
- [ ] 施教反转既有测全绿  
- [ ] 去重重生路径同样触发 HARD 闸  

活库 id 作注释即可，测里用合成字符串，不依赖 `data/qi.db`。

### S4. banned_names

方案 1.2 指出 expression 未传 `banned_names`。本包可：**要么**接上调用方名单，**要么**显式「本包不做，列债务」——不要沉默。
