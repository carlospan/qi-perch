## 必须整改（阻塞编码）

### B1. 「全滤空保留 1 条」会放过 #1367

方案：

```text
return kept if kept else memories[:1]
```

#1367 往往是：检索 top_k 里**全是**无关叙事（或唯一一条就是重置/珍惜）。全滤空后仍 `memories[:1]` → **错记忆照进卡** → 与现状同病。

**整改**：

- 全滤空 → 返回 **`[]`**。  
- 意向卡走空材：`tag=none` + 已有「不编造共同回忆」must；允许短答「嗯 / 好」而不念旧叙事。  
- 若担心「完全没记忆」：可进 `evidence` 记 `topic_gate_empty=1`，**不要**为防空而塞回被拒记忆。

验收改为：菜名 + 仅有重置记忆 → **注入列表为空**（或至少不含「重置/珍惜」），不得「仍保留那条」。

### B2. §3.2「凡 free_talk 记忆都标低置信」过宽

对已通过相关门的记忆仍统一追加 `[话题关联度:低]`，会削弱正当回忆（如用户真在问助眠）。

**整改**：删掉「全体 free_talk 打标」；只对**降级保留**的记忆打标（若仍保留降级路径）。通过闸的记忆保持原文短引。  
更干净：本包**只做过滤、不做低置信注入**；低置信留作可选后续。

### B3. 勿忽略模板放大器（#1367 实测）

`last_intention.outcome == "template"`，回复 ≈ `……嗯。` + memory 原文。即：错记忆进卡后，模板把 primary 念出口。

本包修检索后，建议验收加一条（可轻量）：

- free_talk + materials 为 none 时，模板不得念出「重置/珍惜」类旧文；或  
- 在回执里写明：相关门修完后，template 倾倒问题若仍出现另开小包。

不要求本包大改 expression；但 **B1 必须先让错记忆进不了卡**，否则 template 仍会念错。
