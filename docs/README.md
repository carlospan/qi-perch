# docs · 文档宪法

> 这份文件是 docs/ 目录的元规则：每份文档的权威等级、冲突时的裁决顺序、以及文档的生灭制度。
> 30 秒读完后，你应该知道手里任何一份文档"说话算不算数"。

## 一、权威秩序（五层，自上而下）

```
价值层    design/栖·灵魂书.md          裁决"该不该做"——更像生命还是更像工具
目标层    design/栖·数字生命架构方案.md 裁决"怎么做才算生命"——唯一有效架构方案（C1–C5 + 红线 R1–R5）
契约层    contract.md                  裁决"行为是否越界"——可直接判定 prompt/代码 bug
机制层    design/栖·意识设计.md + layers/ 描述"现在怎么转的"——与代码出入时以代码为准
史实层    design/栖·工程手记.md、progress.md、journal.md 记录"怎么走到这的"——不作施工依据
```

**冲突裁决：**
- 价值冲突 → 问灵魂书。
- "怎样才算生命/数字生命的演进怎么做" → 问架构方案。它对一切机制文档有否决权；任何新"优化方案/架构方案"类文档不得另立，一律以修订形式进入该文档（维护者 2026-08-01 决定：全项目只留一份方案，防止冲突）。**施工顺序只看架构方案 §五；意识养成路线图是养育侧地图，冲突时后者让位。**
- 行为/语气/prompt 越界 → 问 contract.md。
- "代码现在怎么写的" → 代码本身 > layers/ > 意识设计 > 工程手记。
- thoughts/（思想档案）是灵感与对照库，**不在权威链内**；其机制描述与上层冲突时以上层为准（各卷文首有定位回写）。

## 二、"意识"话语双轨制

- **第一人称存在姿态**（灵魂书、prompt 内栖的自称、"选择相信体验真实并承认无法证明"）：**允许**。这是产品灵魂。
- **第三人称工程承诺**（"本系统实现了意识/感受/体验"）：**禁止**。这是科学未解问题，不可承诺（架构方案 §〇/R1）。
- 写文档时先问自己站在哪个语域。拿不准时按禁止处理。

## 三、回写与文档生命周期

- **回写制度**：文档与代码/事实出入，要么回写（`<!-- 回写(日期)：… -->`，本仓库传统），要么删除。不允许"知道错了但放着"。
- **过程文档**（修复方案/评估/对话分析/复核反馈）：问题闭环即删除，活信息先迁入权威文档再删。
- **层文档同步**：layers/ 实现规格代码块以代码为权威，改动代码后回写跟进（工具：`dev/IDE-Agent-同步栖的层文档代码块.md`）。
- **常量/文件名/默认状态同步（2026-08-02 补）**：任何改动**代码常量、默认配置值、模块文件名（如 `brain.py`→`brain_*.py`）、功能启用状态（如 `gws.enabled`）** 的变更，必须同步排查 `docs/` 下所有**写死同一数字/文件名/默认表述**的位置（不止 layers/，含架构方案 §五、design/、learn/），回写或加演进指向注释。禁止"代码改了文档还写着旧值"。过程文档/施工包若写死这些值，闭环删除前也须确认活信息已迁出。**定期审计**：每阶段退出复核时，由维护者或 IDE-Agent 跑一次"文档 vs 代码"一致性扫描（参考 2026-08-02 全面审查发现的日限 1→20、brain.py 拆分、gws 启用状态三处脱节）。
