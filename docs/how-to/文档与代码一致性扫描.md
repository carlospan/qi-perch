# 文档与代码一致性扫描（阶段退出 / 大改后）

> **定位**：how-to。什么时候、怎么扫「docs 是否还跟得上代码」。  
> **纪律真源**：`docs/README.md` 第四节；`specs/SDD-GUIDE.md` §四。  
> **不做**：日常每个小 commit 全库扫描；**阶段退出**或改了常量/模块名/默认配置后必做。

---

## 何时跑

- 任一 `specs/stages/stage-*.md` **退出前**
- 改了：代码常量、默认配置、模块文件名、功能开关（如 `gws.enabled`）
- 大批迁档 / 改文档宪法入口后（抽查活链）

## 扫什么（最短清单）

1. **config 单源**：`settings.example.yaml` ↔ `reference/config.md`（禁手抄第二权威默认值）  
2. **层文档**：改过的 `qi/**` ↔ 对应 `reference/layers/L*.md`（实现规格段）  
3. **progress / 任务指针**：现行能力是否仍指向已迁走的 `tasks/` 死链（应改 `archive/…`）  
4. **contract**：预算日限、确认策略、意图铁律是否与现码一致  
5. **stages**：退出表里的硬判据是否仍可操作（工具/路径是否还在）

## 怎么跑（人工 + 可选脚本）

```text
1. 列出本阶段/本包改过的常量与模块名
2. 在 docs/ 内搜索旧值、旧路径、旧文件名
3. 活链：打开 tasks/README、archive/INDEX、冻结稿「下一步」、progress 近两周条目
4. 有出入 → 回写权威文，或加 <!-- 回写(日期) -->；禁止「知道错了放着」
```

可选：仓库若有 docs 死链 CI / `how-to/ide-agent/IDE-Agent-仓库健康审计.md`，阶段退出时跑一遍。

## 产出

- 在 `progress.md` 记一行「阶段退出 / 一致性扫描：通过或列出已修项」  
- 活信息已进权威文的过程稿，确认在 `specs/archive/`（不删）
