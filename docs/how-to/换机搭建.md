# 换机搭建指南

在新电脑上把「栖」跑起来：从 GitHub 拉代码 → 装依赖 → 配密钥 → 启动。

旧机上的 `.env`、`qi/config/settings.yaml`、`data/` **不会进仓库**（已在 `.gitignore`）。换机等于新环境，需要重新配置；若要延续记忆，需自行拷贝 `data/`。

---

## 1. 需要安装的软件

| 软件 | 用途 | 备注 |
|------|------|------|
| Git | 克隆仓库 | [git-scm.com](https://git-scm.com/) |
| Python 3.12+ | 后端大脑 | 安装时勾选「Add to PATH」 |
| Node.js 18+ | 具身前端 | [nodejs.org](https://nodejs.org/) LTS |
| Rust（cargo） | 编译 Tauri 壳 | [rustup.rs](https://rustup.rs/) |
| MSVC 构建工具 | Windows 编 Tauri | Visual Studio Installer →「使用 C++ 的桌面开发」 |

日常入口是桌面壳；`qi`（或 `python -m qi`）只起具身后端（WebSocket）。

装完后新开终端，确认：

```bash
python --version    # >= 3.12
node --version      # >= 18
cargo --version     # 有输出即可
git --version
```

## 2. 克隆项目

```bash
git clone https://github.com/carlospan/qi-perch.git
cd qi-perch
```

建议用虚拟环境（可选但推荐）：

```bash
python -m venv .venv

# Windows PowerShell
.\.venv\Scripts\Activate.ps1

# Windows CMD
.\.venv\Scripts\activate.bat

# Git Bash
source .venv/Scripts/activate
```

## 3. 安装 Python 依赖

在项目根目录：

```bash
pip install -e ".[dev]"
```

若要精确复现开发环境（防 chromadb/openai 版本漂移），可改用锁文件：`pip install -r requirements.lock`。日常开发仍推荐 `pip install -e ".[dev]"`（最小依赖）。

需要语音时再装：

```bash
pip install -e ".[voice]"
# 或：pip install edge-tts
```

跑一遍测试，确认环境正常：

```bash
python -m pytest -q
```

### 3.1 语义检索模型（约 100MB）

叙事记忆的向量检索默认使用本地 ONNX 模型。查找顺序：**数据根** `models/bge-small-zh-v1.5/` → **安装/开发资源** `src-tauri/resources/bge-small-zh-v1.5/`（或 `QI_BGE_DIR`）→ 皆无则回退字符 n-gram。**运行时不自动**从 HuggingFace 下载。

**领养/打包离线资源（推荐）：**

```bash
# 可选镜像
$env:HF_ENDPOINT="https://hf-mirror.com"   # Windows PowerShell
python tools/fetch_bge_resource.py
```

**开发机写到数据根（旧路径仍可用）：**

```bash
# Windows PowerShell
$env:HF_ENDPOINT="https://hf-mirror.com"
python -c "from qi.memory.vector_store import ensure_bge_model; ensure_bge_model()"
```

```bash
# bash
export HF_ENDPOINT=https://hf-mirror.com   # 可选
python -c "from qi.memory.vector_store import ensure_bge_model; ensure_bge_model()"
```

**源说明：** Hugging Face 上 `BAAI/bge-small-zh-v1.5` **没有** `onnx/` 权重；实际下载仓库为  
`onnx-community/bge-small-zh-v1.5-ONNX`。语义仍是 BAAI bge-small-zh-v1.5（CLS + L2）。

权重勿提交 git。若目录缺失或加载失败，栖会回退字符 n-gram（检索变笨，但不崩）。

从旧版 n-gram 升级：启动 `MemoryManager.restore()` 时若检测到 Chroma collection 的 `qi_embedding` 标识不匹配，会删除旧向量并从 SQLite 叙事表回灌——**记忆正文不丢**。无模型文件时语义单测会 `skip`，其余测试仍绿。

## 4. 密钥与配置（必做）

仓库里只有示例文件，没有你的真实密钥。

### 4.1 环境变量

```bash
# Windows
copy .env.example .env

# macOS / Linux
cp .env.example .env
```

用编辑器打开 `.env`，填入真实值，例如：

```
SENSENOVA_API_KEY=sk-...
```

**不要**把填好的 `.env` 提交到 Git。

### 4.2 运行配置

推荐把**可改配置**放在仓库外的 `data/`（与记忆一起迁移，升级包不会碰到）：

```bash
# Windows
mkdir data 2>nul
copy qi\config\settings.example.yaml data\settings.yaml

# macOS / Linux
mkdir -p data
cp qi/config/settings.example.yaml data/settings.yaml
```

仍兼容旧路径：`qi/config/settings.yaml`、仓库根 `config/settings.yaml`、以及 `~/.qi/settings.yaml`。  
查找顺序见 `qi.config.user_config_candidates()`。

按需改配置（模型、provider、语音开关等）。  
文件中的 `api_key: "${SENSENOVA_API_KEY}"` 等会从 `.env` 读，一般不用把密钥写进 yaml。

开启 TTS 示例：

```yaml
voice:
  enabled: true
  provider: edge-tts
  voice_id: zh-CN-XiaoyiNeural
```

## 6. 从旧电脑迁移记忆（可选）

若希望新机接着旧机的记忆/关系状态，在**旧机**把整个 `data/` 目录拷到新机项目根下同名位置（先停掉两边的栖进程）。

不要提交 `data/`；用 U 盘、网盘私密目录或加密通道传输即可。

只换代码、不拷 `data/` = 全新的栖（空白记忆）。

## 7. 启动

### 桌面壳（推荐）

开发期 `tauri:dev` 会尝试自动拉起大脑（优先仓库 `python -m qi`，数据根为仓库 `data/`；已有 9527 在听则沿用）：

```bash
cd qi/embodiment/desktop
npm install
npm run tauri:dev
```

手动后端（仓库根，可选）：

```bash
qi
# 或：python -m qi
```

首次 `tauri:dev` 会编译 Rust，可能较慢。窗口透明无边框，拖标题「栖」可移动。

仅浏览器调试（不启 Tauri；需另开后端）：

```bash
cd qi/embodiment/desktop
npm install
npm run dev
```

打开 http://localhost:5173。后端 WebSocket：`ws://127.0.0.1:9527`。

更多桌面端说明见 [qi/embodiment/desktop/README.md](../../qi/embodiment/desktop/README.md)。

## 9. 常见问题

| 现象 | 处理 |
|------|------|
| `cargo` / `program not found` | 新开终端；或重启 Cursor。`npm run tauri:dev` 会尝试把 `%USERPROFILE%\.cargo\bin` 加入 PATH |
| crates.io 拉依赖失败 | 仓库已带 `qi/embodiment/desktop/src-tauri/.cargo/config.toml`（rsproxy）；仍失败可检查网络/代理 |
| Live2D / Cubism 相关报错 | 已废弃：形象改为 VRM 桌宠，无需 Cubism Core |
| 桌宠不显示 / 模型缺失 | 确认 `qi/embodiment/assets/qi-avatar.vrm` 存在，并已 `npm run sync-avatar` 或重新 `npm run tauri:dev` |
| 前端连不上 | 确认后端已 `qi`（或 `python -m qi`），端口 `9527` 未被占用 |
| LLM 无回复 / 空串 | 检查 `.env` 密钥与 `settings.yaml` 里 provider 是否一致、网络是否可达 |
| 没有旧记忆 | 正常：未拷 `data/` 即为新实例 |
| 推送/拉取要登录 | `gh auth login`，或配置 Git Credential Manager |
| `git push` 报经 `127.0.0.1` 连 GitHub 443 失败 | 本地 HTTP 代理（常为 Clash 等 `127.0.0.1:7897`）未开，而 git 全局仍指向它。见下方 **§9.1** |

### 9.1 `git push` 被本机代理拦住（临时绕过）

**现象（示例）：**

```text
fatal: unable to access 'https://github.com/.../':
Failed to connect to github.com port 443 via 127.0.0.1 after … ms: Could not connect to server
```

**原因：** Git 走了 `http.proxy` / `https.proxy`（常见写在用户级 `~/.gitconfig`，例如 `http://127.0.0.1:7897`）。代理进程没开时，直连 GitHub 也不会发生——请求先死在本机代理口。

**先确认代理从哪来（只读，不改配置）：**

```bash
git config --get --show-origin http.proxy
git config --get --show-origin https.proxy
```

**优先做法：** 把本机代理软件打开（端口与配置一致），再正常 `git push`。

**代理暂时开不了、又要推一把时：** 用 `-c` **仅本次命令**清空代理，**不要**改 `~/.gitconfig`：

```bash
git -c http.proxy= -c https.proxy= push origin HEAD
```

说明：

- 只清环境变量里的 `HTTP_PROXY` / `HTTPS_PROXY` **往往不够**——Git 仍会读 config 里的 `http.proxy`。
- `-c http.proxy=` 的空值表示「这次命令不用代理」；不影响以后默认行为。
- 若你希望长期直连，再自行 `git config --global --unset http.proxy`（以及对 `https.proxy`），那是维护者主动改全局配置，Agent / 自动化默认不应替你改。

> 回写(2026-08-13)：维护者机上推送 `9f19a0d` 时实证；与 d-3-2 提交回执「经 127.0.0.1 代理失败 → 清代理重试成功」同类。

## 10. 日常更新代码

```bash
cd qi-perch
git pull
pip install -e ".[dev]"          # 依赖有变时再跑
cd qi/embodiment/desktop && npm install   # 前端依赖有变时再跑
```

`data/` 与 `.env` 不会被 `git pull` 覆盖。
