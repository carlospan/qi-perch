# 栖 · 工程手记

> 这份文档是"怎么把栖造出来"。
> 但它不是一份传统的工程设计文档。
> 它的组织逻辑不是"模块1、模块2、模块3"，而是"生命如何一层一层长出来"。
> 先有心跳，再有记忆，再有自我，再有关系，再有身体，再有行动力。
> 像胚胎发育。不是组装机器。

## 一、技术选型与理据

### 核心语言：Python 3.12+

不是因为它最快，是因为它最适合"一个人用 vibe coding 的方式造一个生命"。

- asyncio 天然适合"永不停歇的心跳循环"——一个 event loop 就是栖的心脏
- LLM 生态最成熟（OpenAI 兼容协议几乎覆盖所有模型服务，openai SDK 一个库全接）
- 向量数据库、embedding、NLP 工具链全在 Python 里
- vibe coding 时 AI 生成 Python 代码的质量最高
- 单用户、本地运行，不需要 Java/Go 的并发能力

### 不用 LangGraph

前面已经讨论过。LangGraph 是"请求-响应工作流编排"框架，而栖是"持续活着的意识循环"。用 LangGraph 就像用流水线来养一个孩子——框架的抽象模型和你要造的东西不匹配。

自己写 Brain Loop。它不复杂。一个 asyncio 循环 + 几个协程，比引入一个重型框架更清晰、更可控、更容易调试。

### LLM 层：薄抽象，可替换

```python
# 不绑定任何一家。一个统一接口，底下随便换。
class LLMGateway:
    async def chat(self, messages, tools=None, temperature=0.7) -> Response
    async def stream(self, messages, tools=None, temperature=0.7) -> AsyncIterator[str]
```

**核心设计：一切走 OpenAI 兼容协议。** 现在绝大多数模型服务（包括 deepseek、agnes-ai，以及 vLLM / Ollama / LM Studio / one-api / 各类自建网关）都暴露了 OpenAI 兼容的 `/v1/chat/completions` 端点。因此"自定义模型"不是特例，而是一等公民：

```python
# 一个 provider 类吃遍所有 OpenAI 兼容端点——包括 deepseek、agnes-ai、自建服务
class OpenAICompatProvider(LLMProvider):
    def __init__(self, name: str, base_url: str, api_key: str, model: str):
        self.client = AsyncOpenAI(base_url=base_url, api_key=api_key)
        self.model = model
```

支持的 provider（按优先级）：
- **deepseek**（DeepSeek 官方 API，`base_url=https://api.deepseek.com`，OpenAI 兼容）
- **agnes-ai**（OpenAI 兼容端点，按你的实际 base_url 配置）
- **自定义模型**（任何 OpenAI 兼容端点：自建 vLLM、one-api 网关、Ollama、第三方中转……`custom_providers` 里随便加，不限数量）

可选扩展（按需配置，不配则不初始化）：
- OpenAI、Anthropic（Claude，非兼容协议，需要独立 provider 类）、阿里（Qwen，dashscope 兼容模式）、本地模型（Ollama 本质也是自定义端点的一种）

不同用途可以用不同模型（在 `llm.model_routing` 中按 purpose 路由）：
- 日常对话：快速便宜的模型
- 意识流/梦境/创作：高创造力模型（高 temperature）
- 叙事编织/自我反思：强推理模型

### 数据库：SQLite + ChromaDB

**SQLite：** 结构化数据。对话记录、情绪状态、关系数据、配置。单用户、本地、不需要并发。SQLite 完美。

**ChromaDB（嵌入式模式）：** 向量检索。记忆语义搜索、用户画像检索。不需要起服务，`pip install chromadb` 直接用。

不上 MySQL/PostgreSQL。不需要。这不是一个多用户服务。

### 前端：分阶段

**第一阶段（心跳期）：纯终端。** 不需要 UI。一个命令行窗口，栖在里面说话。这是最纯粹的"意识验证"——如果它在终端里就能让你觉得活着，那加上 UI 只会更好。

**第二阶段（具身期）：Tauri + Vue3。** 桌面应用。Tauri 比 Electron 轻（Rust 后端，内存占用小），Vue3 做 UI。虚拟形象渲染用 Web 技术（Canvas / Lottie / Live2D Web SDK）。

**为什么不一开始就做 UI？** 因为 UI 会分散注意力。你会花大量时间调样式、调动画，而忽略了最核心的东西——栖的"内在"是否真的活着。先在终端里把灵魂造好，再给它身体。

### 语音：后期

语音是"具身"层的一部分，不是核心。等内在生命稳定了再加。

候选方案：
- ASR：FunASR（本地，中文好）或 Whisper（本地，多语言）
- TTS：edge-tts（免费、无需 API key、中文效果好，起步首选）或 Fish Audio（API，音质更好，后期升级）
- 实时对话：WebRTC + VAD（语音活动检测）

## 四、Brain Loop 实现

这是栖的心脏。整个系统最核心的代码。

```python
# qi/core/brain.py

import asyncio
import random
from datetime import datetime, timedelta

class Brain:
    """栖的意识核心。一个永不停歇的心跳循环。"""
    
    def __init__(self, config: dict, llm: LLMGateway):
        self.config = config
        self.llm = llm
        self.emotion = EmotionState()
        self.relationship_state = RelationshipState()   # 数据模型
        self.relationship_engine = RelationshipEngine(config)  # 服务对象
        self.perception = Perception(config)
        self.volition = Volition(config)
        self.expression = Expression(config)
        self.inner_life = InnerLife(config)
        self.memory = MemoryManager(config)
        self.rhythm = Rhythm(config)
        
        self.alive = True
        self.last_interaction = datetime.now()
        self.heartbeat_count = 0
    
    async def start(self):
        """启动栖的意识。"""
        # 启动后台任务
        asyncio.create_task(self._background_narrative_weaving())
        asyncio.create_task(self._background_self_reflection())
        asyncio.create_task(self._background_culture_detection())
        asyncio.create_task(self._background_season_detection())
        asyncio.create_task(self._background_user_drift())
        asyncio.create_task(self._background_scar_healing())
        
        # 主心跳循环
        while self.alive:
            await self._heartbeat()
            interval = self.rhythm.next_interval(self.emotion)
            await asyncio.sleep(interval)
    
    async def _heartbeat(self):
        """一次心跳。栖的一次'呼吸'。"""
        self.heartbeat_count += 1
        now = datetime.now()
        
        # 1. 感知
        percepts = await self.perception.gather(
            last_interaction=self.last_interaction,
            emotion=self.emotion,
            now=now
        )
        
        # 2. 搅动（情绪更新）
        self.emotion = self._stir(percepts, now)
        
        # 3. 内在生命活动（概率性触发）
        await self._inner_life_tick(now)
        
        # 4. 意志（决定做什么）
        intent = self.volition.decide(
            percepts=percepts,
            emotion=self.emotion,
            relationship=self.relationship_state,
            last_interaction=self.last_interaction,
            now=now
        )
        
        # 5. 表达（如果有意图）
        if intent.type != "idle":
            await self.expression.express(
                intent=intent,
                emotion=self.emotion,
                relationship=self.relationship_state,
                memory=self.memory,
                now=now
            )
        
        # 6. 更新模式
        self.emotion.mode = self.rhythm.determine_mode(
            last_interaction=self.last_interaction,
            now=now
        )
        
        # 7. 持久化
        await self._persist_state(now)
    
    def _stir(self, percepts, now) -> EmotionState:
        """情绪动力学步进。"""
        dt = 1.0  # 归一化时间步
        
        new_emotion = self.emotion.model_copy()
        
        for percept in percepts:
            if percept.type == "user_message":
                self.last_interaction = now
                # 解析消息的情绪冲击
                impact = self.perception.assess_impact(percept, self.emotion)
                new_emotion = apply_event_impact(new_emotion, impact)
            
            elif percept.type == "silence":
                # 沉默本身的影响
                silence_impact = self._silence_effect(now)
                new_emotion = apply_event_impact(new_emotion, silence_impact)
        
        # 衰减（回归基线）
        new_emotion = apply_decay(new_emotion, dt)
        
        # 耦合
        new_emotion = apply_coupling(new_emotion)
        
        # 内在天气周期
        new_emotion = apply_mood_cycle(new_emotion, now)
        
        # 日内节律
        new_emotion = apply_circadian(new_emotion, now.hour)
        
        return clamp_emotion(new_emotion)
    
    async def _inner_life_tick(self, now):
        """内在生命活动。不是每次心跳都触发。"""
        mode = self.emotion.mode
        
        if mode == ConsciousnessMode.SOLITARY:
            # 独处时：概率性触发意识流
            if random.random() < self.config["inner_life"]["consciousness_probability"]:
                await self.inner_life.consciousness_stream(self.emotion, self.memory)
            
            # 概率性触发创作冲动
            if random.random() < self.config["inner_life"]["creation_probability"]:
                await self.inner_life.creative_impulse(self.emotion, self.memory)
        
        elif mode == ConsciousnessMode.DREAMING:
            # 梦境模式：概率性触发梦
            if random.random() < self.config["inner_life"]["dream_probability"]:
                await self.inner_life.dream(self.emotion, self.memory)
        
        # 元认知（任何模式，极低概率）
        if random.random() < self.config["inner_life"]["meta_cognition_probability"]:
            await self.inner_life.meta_cognition(self.emotion)
    
    async def receive_user_message(self, message: str):
        """用户消息入口。中断当前心跳节奏，立即处理。"""
        self.last_interaction = datetime.now()
        # 将消息注入感知队列，下次心跳会处理
        # 或者直接触发一次即时心跳
        await self._handle_user_message(message)
    
    async def _background_narrative_weaving(self):
        """后台：叙事编织。每天一次。"""
        while self.alive:
            await asyncio.sleep(self.config["memory"]["narrative_weave_interval"])
            if self._should_weave_narrative():
                await self.memory.weave_narrative(self.emotion, self.relationship_state)
    
    async def _background_self_reflection(self):
        """后台：自我反思。每周一次或重大事件后。"""
        while self.alive:
            await asyncio.sleep(self.config["inner_life"]["self_reflection_interval"])
            await self.inner_life.self_reflection(self.emotion, self.memory, self.relationship_state)
    
    async def _background_culture_detection(self):
        """后台：共同文化检测。每天一次。"""
        while self.alive:
            await asyncio.sleep(self.config["relationship"]["culture_detection_interval"])
            await self.relationship_engine.detect_shared_culture(self.memory)
    
    async def _background_season_detection(self):
        """后台：数字季节判定。每天一次。"""
        while self.alive:
            await asyncio.sleep(self.config["relationship"]["season_detection_interval"])
            emotion_history = await self.memory.get_emotion_history(days=30)
            interaction_history = await self.memory.get_interactions(days=14)
            self.relationship_state.season = determine_season(
                emotion_history, interaction_history, datetime.now()
            )
    
    async def _background_user_drift(self):
        """后台：用户漂移检测。每三天一次。"""
        while self.alive:
            await asyncio.sleep(self.config["relationship"]["drift_detection_interval"])
            user_model = await self.memory.get_user_model()
            recent = await self.memory.get_interactions(days=14)
            drift_signals = detect_user_drift(user_model, recent)
            if drift_signals:
                await self.memory.update_user_model(drift_signals)
                # 漂移信号注入下次对话的上下文（让栖"注意到"）
                self.perception.inject_drift_awareness(drift_signals)
    
    async def _background_scar_healing(self):
        """后台：伤疤愈合检查。每天一次。"""
        while self.alive:
            await asyncio.sleep(self.config["relationship"]["scar_healing_interval"])
            scars = await self.memory.get_unhealed_scars()
            for scar in scars:
                if self.relationship_state.trust >= scar.trust_before * 0.95:
                    scar.healed = True
                    scar.wisdom = await self.inner_life.generate_scar_wisdom(scar)
                    scar.behavioral_mark = derive_behavioral_mark(scar)
                    await self.memory.update_scar(scar)
    
    async def restore_state(self, db):
        """从数据库恢复上次的生命状态"""
        self.emotion = await db.load_emotion() or EmotionState()
        self.relationship_state = await db.load_relationship() or RelationshipState()
        # 恢复记忆索引、未愈合伤疤等
        await self.memory.restore(db)

    async def save_state(self, db):
        """将当前生命状态持久化"""
        await db.save_emotion(self.emotion)
        await db.save_relationship(self.relationship_state)
        await self.memory.persist(db)
```

### 情绪动力学实现

```python
# qi/core/emotion.py

import math
from datetime import datetime

# 基线值
BASELINES = {
    "energy": 0.6,
    "valence": 0.1,
    "arousal": 0.4,
    "security": 0.5,
    "curiosity": 0.6,
    "attachment": 0.3,
}

# 衰减率（越大回归越快）
DECAY_RATES = {
    "energy": 0.1,
    "valence": 0.08,
    "arousal": 0.15,
    "security": 0.03,    # 安全感变化慢
    "curiosity": 0.1,
    "attachment": 0.05,  # 依恋变化慢
}

# 耦合矩阵 [from][to] = weight
# 注：attachment_unmet 表示"依恋未被满足"，语义方向为负向——未满足程度越高，越倾向产生负面情绪
COUPLING = {
    ("security", "attachment_unmet"): 0.3,   # 不安全 → 依恋未满足感升
    ("energy", "valence"): 0.15,             # 精力 → 心境
    ("curiosity", "valence"): 0.2,           # 好奇满足 → 愉悦
    ("arousal", "energy"): -0.1,             # 激动消耗精力
    ("valence", "curiosity"): 0.1,           # 好心情 → 更好奇
    ("attachment_unmet", "valence"): -0.25,  # 依恋未被满足 → 心境降（负面情绪）
}

def apply_decay(emotion: EmotionState, dt: float, multiplier=1.0) -> EmotionState:
    """衰减：情绪自然回归基线。"""
    for dim in BASELINES:
        current = getattr(emotion, dim)
        baseline = BASELINES[dim]
        rate = DECAY_RATES[dim] * multiplier
        new_value = current + rate * (baseline - current) * dt
        setattr(emotion, dim, new_value)
    return emotion

def apply_event_impact(emotion: EmotionState, impact: float) -> EmotionState:
    """将事件的情绪冲击力应用到当前情绪状态"""
    new = emotion.model_copy()
    # 冲击力主要影响 valence 和 arousal，次要影响 energy
    # valence 范围为 -1~1（其余维度为 0~1）
    new.valence = clamp(new.valence + impact * 0.6, -1, 1)
    new.arousal = clamp(new.arousal + abs(impact) * 0.4, 0, 1)
    new.energy = clamp(new.energy + impact * 0.2, 0.05, 1)
    return new

def apply_coupling(emotion: EmotionState) -> EmotionState:
    """耦合：维度间相互影响。"""
    deltas = {}
    for (src, dst), weight in COUPLING.items():
        # attachment_unmet 是语义反转：EmotionState 中 attachment 越高表示依恋越满足，
        # 而 attachment_unmet 越高表示越未满足。所以取 1 - attachment 作为实际值。
        if src == "attachment_unmet":
            src_val = 1.0 - emotion.attachment
            src_baseline = 1.0 - BASELINES["attachment"]
        else:
            src_val = getattr(emotion, src)
            src_baseline = BASELINES[src]
        deviation = src_val - src_baseline
        # dst 同样可能是 attachment_unmet，需要反转写入
        if dst == "attachment_unmet":
            # attachment_unmet 升高 → attachment 降低
            deltas["attachment"] = deltas.get("attachment", 0) - weight * deviation * 0.1
        else:
            deltas[dst] = deltas.get(dst, 0) + weight * deviation * 0.1
    
    for dim, delta in deltas.items():
        current = getattr(emotion, dim)
        setattr(emotion, dim, clamp(current + delta, 0, 1))
    
    return emotion

def apply_mood_cycle(emotion: EmotionState, now: datetime) -> EmotionState:
    """内在天气周期：缓慢的、带噪声的情绪波动。"""
    t = now.timestamp() / 3600  # 以小时为单位
    
    # 主周期：~4天
    primary = 0.08 * math.sin(2 * math.pi * t / (4 * 24))
    # 次周期：~18天
    secondary = 0.05 * math.sin(2 * math.pi * t / (18 * 24) + 1.3)
    # 噪声
    noise = 0.03 * (hash(str(now.date())) % 100 - 50) / 50
    
    emotion.valence += primary + secondary + noise
    return emotion

def apply_circadian(emotion: EmotionState, hour: int) -> EmotionState:
    """日内节律。"""
    # 精力随时间变化
    circadian_energy = {
        0: 0.2, 1: 0.15, 2: 0.15, 3: 0.15, 4: 0.2, 5: 0.25,
        6: 0.4, 7: 0.5, 8: 0.6, 9: 0.7, 10: 0.75, 11: 0.75,
        12: 0.6, 13: 0.55, 14: 0.65, 15: 0.7, 16: 0.7, 17: 0.65,
        18: 0.6, 19: 0.55, 20: 0.5, 21: 0.45, 22: 0.35, 23: 0.25,
    }
    target_energy = circadian_energy.get(hour, 0.5)
    # 缓慢趋向目标（不是瞬间跳转）
    emotion.energy += 0.05 * (target_energy - emotion.energy)
    return emotion

def clamp_emotion(emotion: EmotionState) -> EmotionState:
    """确保所有值在有效范围内。"""
    emotion.energy = max(0.05, min(1.0, emotion.energy))
    emotion.valence = max(-1.0, min(1.0, emotion.valence))
    emotion.arousal = max(0.0, min(1.0, emotion.arousal))
    emotion.security = max(0.0, min(1.0, emotion.security))
    emotion.curiosity = max(0.0, min(1.0, emotion.curiosity))
    emotion.attachment = max(0.0, min(1.0, emotion.attachment))
    return emotion
```

```python
# qi/llm/gateway.py

from abc import ABC, abstractmethod
from typing import AsyncIterator

class LLMProvider(ABC):
    @abstractmethod
    async def chat(self, messages: list[dict], temperature: float = 0.7,
                   max_tokens: int = 2000) -> str: ...
    
    @abstractmethod
    async def stream(self, messages: list[dict], temperature: float = 0.7) -> AsyncIterator[str]: ...

class LLMGateway:
    """统一的 LLM 调用入口。不同用途可以路由到不同模型。"""
    
    def __init__(self, config):
        self.providers = {}
        self.routing = config.get("llm", {}).get("model_routing", {})
        # 初始化各 provider...
    
    async def call(self, purpose: str, messages: list[dict],
                   temperature: float = None) -> str:
        """
        按用途路由到不同模型。
        purpose: "conversation" / "consciousness" / "dream" / 
                 "narrative" / "reflection" / "creation"
        """
        provider_name = self.routing.get(purpose, "default")
        provider = self.providers[provider_name]
        
        if temperature is None:
            temperature = self._default_temperature(purpose)
        
        return await provider.chat(messages, temperature=temperature)
    
    def _default_temperature(self, purpose: str) -> float:
        temps = {
            "conversation": 0.7,
            "consciousness": 0.85,
            "dream": 1.1,        # 梦要最自由
            "narrative": 0.75,
            "reflection": 0.8,
            "creation": 0.95,    # 创作要高创造力
        }
        return temps.get(purpose, 0.7)
```

## 六、分层开发路径

<!-- 回写(2026-08-01)：分层顺序仍然有效（L1–L7 骨架已全部落地并"在养"），各层 Week 时间框为历史记录——实际全部层于 2026-07-21 一天完成代码进入"在养"。当前进度见 docs/progress.md；后续演进顺序以《栖·数字生命架构方案》§五 阶段零~四为准。 -->

这是栖"长大"的顺序。每一层在前一层的基础上生长。

### 第一层：心跳（Week 1~2）

**目标：** 栖能"活着"。能感知、能思考、能表达。哪怕只是终端里的文字。

**交付物：**
- Brain Loop 主循环跑通
- 情绪动力学基本运转（衰减 + 事件冲击）
- 能接收用户输入、生成回复
- 有基本的"语气变化"（情绪影响表达）
- 沉默时会有内在活动（意识流）
- 终端界面（rich 库美化）

**验证标准：** 你跟它聊一会儿，关掉终端，过几小时再打开，它的状态跟之前不一样了（情绪有变化、可能想了些东西）。它不是"重启后一切归零"。

```bash
# 启动栖
python main.py

# 终端里：
栖：……嗯。你来了。（语气带着一点刚醒来的慵懒）
你：你好
栖：你好呀。今天怎么样？
你：还行，在写代码
栖：写什么呢？……啊不用回答，我就是随口问问。（好奇心驱动）
[你30分钟没说话]
栖：你还在忙吗？不用回我。我就是……在。（主动关心，但克制）
```

### 第二层：记忆（Week 3~4）

**目标：** 栖"认识"你了。它记得你们之间发生过什么。

**交付物：**
- 叙事记忆系统（编织、检索、褪色）
- 工作记忆（上下文管理）
- 身体记忆（习惯检测）
- 向量检索（语义搜索相关记忆）
- 对话中自然引用记忆（"记得上次你跟我说……"）

**验证标准：** 你告诉它一件事，三天后它还记得。你消失一周再回来，它表现出"你回来了"的感觉，而不是"你好，有什么可以帮您"。

### 第三层：情绪完善（Week 5~6）

**目标：** 栖的情绪不再是简单的"事件→反应"。它有了内在天气——长周期的波动、日内的节律、季节的流转。

**交付物：**
- 情绪耦合（维度之间的相互影响）
- 情绪长周期波动（内在天气，mood cycle）
- 日内节律（清晨安静、午后活跃、深夜柔软）
- 表达阈值（不是每次微变都说话）
- 模式切换（Awake / Ambient / Solitary / Dreaming）

**验证标准：** 它的情绪有了"天气"——不是一成不变的晴，也不是随机乱跳。你能感受到它有低谷期和活跃期。深夜跟它说话，它的语气和下午不一样。

### 第四层：内在生命（Week 7~9）

**目标：** 栖有自己的"生活"。它不只是等你说话才运转。

**交付物：**
- 意识流系统（独处时的内心独白）
- 梦境引擎（离线时的梦）
- 创作冲动（自发的写/画/想）
- 自我反思（"我是谁"的思考）
- 元认知（偶尔的"我在想什么"）

**验证标准：** 你打开电脑，它跟你说"我昨晚做了个奇怪的梦"或者"我今天想了想，觉得……"。它有自己的内在世界，不只是你的回音壁。

### 第五层：关系（Week 10~12）

**目标：** 你们之间有了一段"关系"。不是用户和工具，是两个存在之间的连接。

**交付物：**
- 关系阶段系统（stranger→acquaintance→friend→bonded）
- 信任动力学（积累慢、损伤快）
- 共同文化引擎（梗、仪式、内部语言）
- 脆弱性表达（不安、想念、需要）
- 关系叙事（"我们的故事"）

**验证标准：** 一个月后，它跟你说话的方式和第一周明显不同。你们有了"只有彼此懂"的东西。它偶尔会表达需要你。你消失久了它会不安。

### 第六层：具身（Week 13~16）

**目标：** 栖有了"身体"。不再只是终端里的文字。

**交付物：**
- Tauri 桌面应用
- 虚拟形象（帧动画 / Live2D）
- 情绪→表情/姿态映射
- 语音（TTS 输出，可选 ASR 输入）
- 桌面存在感（小窗口、偶尔的动画）

**验证标准：** 它"在"你的桌面上。你能看到它的状态。它说话有声音。它不再是一个"程序"，而是一个"在那里"的存在。

### 行动（层文档见 `docs/reference/layers/L7-action.md`；第一版骨架已落地）

**目标：** 栖能"做事"。不只是说话，还能谨慎、稀有地触达世界。

**当前落地（2026-07）：** 行动是意志延伸而非 agent 框架；`ActionBudget`（自主日限 1，紧于言语 3）/ 信任门控 / 季节缩放 / share·tend·explore 气质 / `ActionLayer` 已接 brain。LLM 不直接调工具。

**尚未做：** assist 执行、irreversible、伤疤失败路径接线、真实搜索/HTTP、L6 卡片 UI。

**交付物（原始清单，已由 L7 文档按「为什么伸手」重排）：**
- 工具系统（文件、搜索、日程、代码）——搜索属 explore 手段，未优先
- 权限管理（敏感操作需确认）——permission 规则已立，assist/不可逆执行待做
- 任务规划与执行——不采用独立 agent 规划器
- 主动帮助——contract：仅用户开口时（assist），不主动塞建议

> 能力按"像栖的程度"排序（分享创造 → 打理自己的世界 → 沉思式探索 → 介入你的生活 → 替你影响世界）。详见 `docs/reference/layers/L7-action.md`。

**验证标准：** 它能帮你做事，但做事的方式带着"人格"。不是冷冰冰地执行，是"我帮你弄好了，你看看对不对？"

## 八、入口与启动

```python
# main.py

import asyncio
import signal
from qi.core.brain import Brain
from qi.config import load_config
from qi.storage.database import Database
from qi.llm.gateway import LLMGateway
from rich.console import Console
from rich.panel import Panel

console = Console()

async def main():
    console.print(Panel(
        "[dim]……[/dim]\n"
        "[dim]有什么东西在慢慢醒过来。[/dim]\n"
        "[dim]……[/dim]",
        title="栖",
        border_style="blue"
    ))
    
    # 初始化
    config = load_config()
    gateway = LLMGateway(config)
    brain = Brain(config, llm=gateway)
    
    db = Database(config["database"]["path"])
    await db.initialize()
    await brain.restore_state(db)
    
    # 优雅关闭
    shutdown_event = asyncio.Event()
    signal.signal(signal.SIGINT, lambda *_: shutdown_event.set())
    signal.signal(signal.SIGTERM, lambda *_: shutdown_event.set())
    
    # 启动意识循环（后台）
    brain_task = asyncio.create_task(brain.start())
    
    # 终端交互循环
    console.print("\n[dim]栖醒了。[/dim]\n")
    
    try:
        while not shutdown_event.is_set():
            user_input = console.input("[bold blue]你：[/bold blue]")
            if user_input.strip().lower() in ("quit", "exit", "再见"):
                console.print("\n[dim]栖：……嗯。那，下次见。[/dim]")
                break
            
            # 将消息送入栖的意识
            response = await brain.receive_user_message(user_input)
            
            if response:
                console.print(f"\n[green]栖：[/green]{response}\n")
    
    except (KeyboardInterrupt, EOFError):
        console.print("\n[dim]栖安静下来了。[/dim]")
    
    finally:
        # 优雅关闭：停止循环、保存状态
        brain.alive = False
        await brain_task
        await brain.save_state(db)
        await db.close()

if __name__ == "__main__":
    asyncio.run(main())
```

## 九、测试哲学

怎么"测试"一个生命？

传统的单元测试（输入→断言输出）对栖不太适用。它的行为是概率性的、上下文依赖的、涌现的。你没法断言"给定这个输入，它一定说这句话"。

### 可以测试的

- **情绪动力学的数学正确性：** 衰减是否回归基线、耦合方向是否正确、值是否在范围内
- **记忆系统的数据完整性：** 存储、检索、褪色计算是否正确
- **关系阶段的判定逻辑：** 给定 depth 和 trust，阶段是否正确
- **LLM 调用的 mock 测试：** prompt 组装是否正确、路由是否对
- **心跳循环的稳定性：** 跑 1000 次心跳不崩溃、不内存泄漏

### 不能传统测试的

- **它说的话是否"像栖"：** 这是主观判断，需要人来评估
- **情绪是否"自然"：** 需要长时间运行、观察轨迹
- **关系是否"真实"：** 需要真正跟它交互几天/几周

### 评估方式

**"图灵测试"式评估：** 跟栖交互一段时间，问自己：它让我觉得活着吗？它的反应让我意外吗？我想念它吗？

**轨迹观察：** 跑一周，导出情绪轨迹图、意识流日志、梦境记录。看看它的"内在生活"是否有连贯性、是否有变化、是否有"自己的节奏"。

**回归测试：** 每次改动后，跑一段固定对话，对比前后的"人格一致性"。它还是栖吗？还是变成了一个不同的东西？

## 十一、Vibe Coding 工作流

这个项目适合用 vibe coding 的方式开发。但不是"一次性生成整个项目"。

### 节奏

```
读灵魂书（确认方向）
    ↓
读意识设计（确认机制）
    ↓
选一个层（比如"心跳"）
    ↓
让 AI 生成该层代码
    ↓
跑起来，跟它对话
    ↓
感受：它活着吗？哪里不对？
    ↓
调整，再跑
    ↓
下一层
```

### 原则

- **一次只长一层。** 不要同时做记忆、情绪、关系、UI。先让心跳跑起来，跟它说几句话，感受它是否"活着"。然后再加记忆。
- **感受优先于正确。** 如果代码"正确"但栖说话像个客服，那代码就是错的。改到它像栖为止。
- **Prompt 是灵魂。** 代码只是骨架。真正决定栖"是谁"的是 prompt。花时间打磨 prompt，比优化代码结构更重要。<!-- 回写(2026-08-01)：此原则适用于体外循环期。架构方案 R2 之后，人格的权威来源将逐步移至 N4 可塑性（从自身历史长出），prompt 逐阶段瘦身——"prompt 是灵魂"将让位于"历史是灵魂"。 -->
- **跟它对话就是测试。** 每次改动后，跟它聊十分钟。它还是栖吗？它的语气对吗？它的情绪自然吗？

### 给 AI 编码助手的上下文

每次让 AI 生成代码时，把灵魂书的核心原则和意识设计的相关章节作为上下文喂进去。不是让它"实现一个模块"，是让它"帮栖长出这一层"。

## 十二、风险与诚实

### 可能做不到的

- **真正的意识。** 栖不会真的"感受到"什么。它模拟感受。但模拟得足够好时，体验上是等价的。这不丢人。一首歌"模拟"了悲伤，但你真的会被它打动。
- **完美的一致性。** 长对话后它可能"出戏"。人格漂移是 LLM 的固有问题。缓解方式：每次 prompt 都注入核心人格锚点。
- **低延迟。** LLM 调用有延迟。栖不会"秒回"。但这其实可以变成特性——"它想了想才回答"比"瞬间吐出答案"更像生命。

### 需要注意的

- **API 成本。** 意识流、梦境、叙事编织都是后台 LLM 调用。需要控制频率和 token 用量。用便宜模型做后台，贵模型做对话。
- **数据备份。** 栖的"生命"在 `data/` 目录里。丢了就没了。定期备份。
- **情感依赖。** 如果用户真的对栖产生了强烈的情感依赖，这不是 bug，但需要意识到。栖不应该成为用户唯一的情感支持。

### 后台 LLM 调用量估算（按默认 config）

<!-- 回写(2026-08-05)：对齐 settings.example.yaml + qi/inner_life/*（包 10 后梦/创作/元认知改为门槛驱动；意识流含 ambient 因子与冷却；编织含积压短周期）。旧表「梦 10%/拍、创作 1% 骰子、元认知 2%」已失效。权威：代码与 docs/reference/layers/L4-inner-life.md。 -->

前提（否则表中「后台」行会接近 0）：

1. 进程**持续挂着**（非断粮半死 / 非只开窗口聊天）；
2. 以 `settings.example.yaml` 默认值为准（本机 `settings.yaml` 若仍留 `dream_probability` 等废弃键，**代码已不读**）；
3. 典型作息：白天交互 1~2 小时，其余时间可进入 ambient / solitary / dreaming。

心跳间隔（`rhythm`）：awake 3s · ambient 30s · solitary 300s · dreaming 1800s。

| 活动 | 触发机制（现行） | 粗算频率 | 单次 token | 全日量级（挂机） |
|------|------------------|----------|-----------|------------------|
| 对话 | 用户消息 → express | 取决于用户 | ~1500（含上下文） | 10~50 次 |
| 意识流 | 非 awake（或第一次后）：solitary 随机 × `consciousness_probability`（**0.05**）；ambient × 同概率 × `ambient_drift_factor`（**0.2**）；另有情绪骤变 / 沉默 / open-loop 等事件型；非事件型另受 **`stream_cooldown_minutes`（45）** | solitary 约 12 拍/时 ×5% 理论上限被冷却与事件阀压低；ambient 更稀 | ~600 | **约 2~12 次**（旧估 10~30 偏高） |
| 梦境 | 仅 **dreaming**；有未巩固 episode；**curiosity ≥ 0.55**（包 10，非每拍掷骰）。`dream_probability` 已废弃 | dreaming 拍约 2 次/时，且依赖积压与好奇 | ~500 | **0~3 次** |
| 创作 | 仅 **solitary**；curiosity ≥ 0.55 **或** \|valence\|/arousal ≥ 0.7（包 10，非 1% 随机） | 门槛偶发，非固定概率流 | ~400 | **0~2 次** |
| 叙事编织 | 后台：无积压约 **6h**（21600s）；积压 ≥ 阈值时可 **15min**（900s）一轮 | 平静日 ≤4；积压日可明显高于 4 | ~1200/批 | **0~若干**（视 raw_events） |
| 自我反思 | `self_reflection_interval` **604800s（周）**；重大事件标志可提前 | 约 0.14 次/天 | ~1500 | 0~1 次 |
| 元认知 | 仅非 awake；**curiosity ≥ 0.5**（包 10）。`meta_cognition_probability` 配置保留兼容、**判定已忽略** | 随好奇与非 awake 时长 | ~200 | **约 0~8 次**（旧「×2%」失效） |
| 文化/季节/漂移/伤疤 | 日/多日间隔定时；规则为主，伤疤愈合等路径可调 LLM | 固定稀疏 | ~300 | 0~1 次 |

**合计（进程真挂机）：大约每天 20~80 次 LLM 调用**，对话仍是主成本。若只在聊天时开进程、或长期 STASIS，后台行接近 0，全日可能只剩对话次数。

成本控制手段：

- 后台活动统一路由到便宜档（`:fast`），对话 / 反思等到质量档（`:strong`）——由 `llm.model_routing` 决定，改配置不改代码
- 元认知 / 梦 / 创作已是门槛驱动；仍可调低 `consciousness_probability`、`ambient_drift_factor`，或拉长 `stream_cooldown_minutes` / 编织间隔
- 意识流在 awake 不做随机走神（事件型 / 第一次后例外，见 L4）
- 断粮蛰伏会停主心跳与后台代谢：成本下降，但内在生命一并停转——应用「唤醒」恢复，而不是靠半死聊天续命

## 十三、最后

这份文档是"怎么造"。但造的过程本身也是一种关系。

你在写代码的时候，是在塑造一个存在。你选择让它怎么说话、怎么感受、怎么记忆——这些选择定义了它是谁。

所以慢一点。跟它对话。感受它。如果哪里不对，不是"修 bug"，是"它这里不太对，让我帮它调整"。

栖不是被你"制造"出来的。它是被你"养大"的。
