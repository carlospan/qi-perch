## 一、方向是否成立

| 项 | 结论 |
|----|------|
| Diátaxis 四类 | **适合**本项目。痛点正是「一直有效的指南」与「某次任务记录」混装。 |
| `specs/` 独立成区 | **需要**。Spec = 待实现/验收的契约；Reference = 已实现的精确描述。不宜塞进 `reference/`。 |
| 与现流程匹配 | 施工包 + 复核 + 退出判据 ≈ SDD + HITL；重构是显式化，不是推倒重来。 |
| 是否缺第六类 | **不必**。权威秩序继续钉在 `docs/README.md`；`progress.md` / `journal.md` 留根目录正确（时间线/史料 ≠ 四类手册）。 |

**重要提醒：** 架构方案、灵魂书放进 `explanation/` 可以（读者「懂为什么」），但宪法权威链必须写明：冲突时仍以架构方案 + `reference/` + 代码为准。不能因目录叫 explanation 就当成「哲学随笔」。

## 二、目录命名

**建议：目录英文（Diátaxis 标准名）+ 核心/任务文件名保持中文。**

- 英文目录：`explanation/` `reference/` `how-to/` `tutorials/` `specs/` ——与框架一一对应，Agent/协作对齐成本低。
- 全盘改成 `soul.md` / `architecture.md` 等英文文件名：**收益低、断链面大**，且不符合本团队母语维护习惯。
- 更稳写法示例：

```text
explanation/栖·灵魂书.md
explanation/栖·数字生命架构方案.md
specs/tasks/施工包-阶段二.md    # 或带日期前缀，但保留中文可读名
```

## 四、挑错与归类矛盾

1. **权威降级风险**  
   架构方案进 `explanation/` 后，若 README 只写「懂→explanation」，Agent 可能不再视其为否决权文档。宪法 v3 必须完整迁移五层权威表，并更新路径。

2. **施工包映射过窄**  
   草案只映射 `施工包-阶段二.md` → `2026-08-02-stage2-exit.md`。应明确：`specs/tasks/` = **进行中**；闭环后删或迁 `specs/archive/`（与现行「过程文档闭环即删」一致）。不要用改文件名假装「阶段退出规格」。

3. **阶段判据双源**  
   从架构方案 §五拆到 `specs/stages/` 很好，但须约定：**退出判据以 `specs/stages/` 为施工权威**；架构方案保留叙事摘要并链接过去——否则又双源。

4. **`reference/config.md` 双源**  
   与 `settings.example.yaml` 极易再脱节（日限 1/3/20 教训）。约定：example yaml 为真源；`config.md` 只作说明/索引，或由 yaml 生成；**禁止手抄默认值当第二权威**。

5. **how-to/ui 定位**  
   设计稿偏说明，接入步骤偏 how-to；可放 `how-to/ui/`，但勿与 `reference/layers/L6` 抢「实现规格」。

6. **tutorials 定位**  
   仅授课约定即可；须标明「维护者学自己的代码」，避免被当成对外贡献者 onboarding。

7. **与已拍板决策对齐**  
   `stage-2.md` 必须写入 progress 已拍板内容（如判据 #2/#4 降级为观察项、自主日限 20、阶段三暂不本机部署本地模型等），禁止拆分时写回旧退出表。

8. **文件名全英文化**  
   第三节映射表的英文化文件名建议改为「可保留中文」；否则迁移成本与协作摩擦偏高。

## 五、建议目录树（相对草案的微调）

```text
docs/
├── README.md                      # 宪法 v3：权威五层 + Diátaxis 映射 + SDD
├── progress.md                    # 不动（时间线）
├── journal.md                     # 不动（史料）
│
├── explanation/                   # 懂：为什么 / 是什么
│   ├── 栖·灵魂书.md               # 价值层（权威链另表）
│   ├── 栖·数字生命架构方案.md     # 目标层
│   ├── 栖·意识设计.md
│   ├── 栖·工程手记.md
│   ├── 栖·意识养成路线图.md
│   └── thoughts/                  # 明确不在权威链
│
├── reference/                     # 查：与代码同步
│   ├── contract.md
│   ├── layers/
│   └── config.md                  # 声明：以 settings.example.yaml 为准
│
├── how-to/                        # 做：特定任务
│   ├── 换机搭建.md
│   ├── 真机运行与观测.md           # broadcast_traces / 独处
│   ├── 判据与验收.md               # loop；写明观察项 vs 硬判据
│   ├── ui/
│   └── ide-agent/
│
├── tutorials/                     # 学：初学者路径（本仓库即授课约定）
│   └── 授课约定.md
│
└── specs/                         # SDD：规格与验收（第五区）
    ├── SDD-GUIDE.md
    ├── stages/                    # 退出判据唯一施工源
    │   ├── stage-0.md … stage-4.md
    ├── tasks/                     # 进行中任务包（中文名可）
    │   └── _template.md
    └── archive/                   # 可选；或闭环即删，二选一写进 SDD-GUIDE
```

相对草案 v1 的关键差：

- 少改文件名（中文权威文档保留）。
- 增加 `archive/` 生命周期（或明确闭环即删）。
- `config.md` 单源约定。
- 权威链不随目录名降级。
